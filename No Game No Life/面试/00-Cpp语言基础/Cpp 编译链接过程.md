## 一句话结论（自测用）
> C++ 编译四阶段：预处理（宏展开/头文件/条件编译）→ 编译（源码→汇编）→ 汇编（汇编→机器码 .o）→ 链接（合并 .o + 库 → 可执行文件）。静态链接在编译期将库代码复制进 exe；动态链接在运行期加载 .so/.dll。

## 标准答案（结构化、可背诵，2分钟内讲完）
1. **预处理**：处理 `#include`（头文件展开）、`#define`（宏替换）、`#ifdef`（条件编译）、`#pragma`。生成 .i 文件（展开后的源文件）。
2. **编译**：词法分析 → 语法分析 → 语义分析 → 中间代码生成 → 优化 → 汇编代码生成。将 .i 文件编译为 .s 汇编文件。
3. **汇编**：汇编器将 .s 转为 .o（目标文件 = 机器码）。此时每个 .cpp 独立编译，函数调用地址用"符号"占位。
4. **链接**：链接器合并所有 .o 和库文件，解析符号引用（将占位的函数名替换为实际地址），进行重定位。生成最终可执行文件（ELF/PE/Mach-O）。

## 详细解析

### 静态库 vs 动态库
| | 静态库 .a/.lib | 动态库 .so/.dll |
|---|---|---|
| 链接时机 | 编译期 | 运行期 |
| exe 体积 | 较大（库代码嵌入） | 较小（只存引用） |
| 更新方式 | 重新编译+链接 | 替换 .so/.dll 即可 |
| 内存占用 | 多进程各有一份 | 共享一份内存 |
| 加载速度 | 快 | 稍慢（运行期解析） |

### 内部链接 vs 外部链接
- **内部链接**（Internal Linkage）：仅在当前编译单元可见。`static` 全局变量/函数、匿名 namespace 中的内容。
- **外部链接**（External Linkage）：可被其他编译单元引用。普通全局变量/函数、非 static 类成员函数。`extern` 声明外部变量/函数。

### extern "C"
C++ 有函数重载，编译时会对函数名做 Name Mangling（编码参数类型信息到符号名）。C 无重载不做 mangling。`extern "C"` 告诉 C++ 编译器按 C 方式编译函数（不做 mangling），使 C++ 函数能被 C 代码调用、或调用 C 库。

```cpp
extern "C" {
    void c_function();  // 按 C 方式编译，符号名就是 c_function
}
```

## 面试官常见追问
- 头文件重复包含怎么解决？（`#ifndef` / `#pragma once` 防止头文件在一个编译单元中被重复包含）
- 链接错误 "undefined symbol" 是什么原因？（函数声明了但没定义；库没链接；函数签名不匹配导致符号名对不上）
- 动态库是怎么加载的？（操作系统动态链接器 ld.so/ld-linux.so 在程序启动时或运行期 dlopen() 加载）
- 静态变量初始化顺序问题？（不同编译单元间的静态变量初始化顺序不确定 —— Static Initialization Order Fiasco）

## 我曾经的误区 / 网上常见错答
- **错**："#pragma once 是标准 C++ 的" —— 是编译器扩展（VS/GCC/Clang 都支持），不是语言标准，但比 #ifndef 更简洁高效
- **错**："编译就是把所有 .cpp 串起来一起处理" —— 每个 .cpp 先独立编译，链接时才合并
- **错**："静态库就是 .o 文件打包" —— 确实是一堆 .o 的归档（ar），但链接时还会做符号解析和优化
