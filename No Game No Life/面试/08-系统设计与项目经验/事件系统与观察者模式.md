## 🎯 一句话结论（自测用）
> 观察者模式的核心：定义一对多依赖关系，当主题状态变化时自动通知所有观察者。游戏中的应用：成就系统（击杀事件 -> 成就检查）、UI 更新（血量变化 -> 血条刷新）、音效播放。关键注意事项：场景切换时必须注销事件注册，否则导致对象无法被 GC 回收（内存泄漏）。

## ✅ 标准答案（结构化、可背诵，2分钟内讲完）
1. **观察者模式的三种 Csharp 实现方式**：
   - `event` / `delegate`：原生支持，性能最高，适合代码内使用
   - `UnityEvent`：可在 Inspector 中可视化配置，性能较低（有反射开销），适合策划/美术手动绑定
   - 自定义 EventManager/MessageCenter：使用 Dictionary<EventType, Delegate>，全局消息总线，统一管理所有事件
2. **事件中心的实现**：Register（注册）、UnRegister（注销）、Trigger（广播）。注意使用弱引用或强制注销机制，防止内存泄漏。
3. **应用场景**：
   - 成就系统：击杀 N 个敌人、达到某等级 -> 成就检查
   - UI 刷新：血量变化 -> 血条更新、金币变化 -> 金币 UI 更新
   - 音效播放：攻击命中 -> 播放命中音效
   - 任务系统：击杀怪物 -> 更新任务进度
4. **核心防坑点**：
   - `OnDestroy`/`OnDisable` 中必须注销事件监听
   - 避免在事件回调中注销当前事件（可能引发迭代异常）
   - 事件参数尽量使用不可变类型

## 🔍 详细解析

### Csharp event vs UnityEvent
| 对比维度 | Csharp event | UnityEvent |
|---------|---------|-----------|
| Inspector 可视化 | 不可 | 可（序列化） |
| 性能 | 高 | 较低（反射） |
| 参数个数 | 无限制 | 最多 4 个（UnityEvent<T0,T1,T2,T3>） |
| 适用场景 | 纯代码绑定 | 编辑器配置绑定 |

### 事件中心实现
```csharp
public class EventCenter
{
    private static Dictionary<string, Delegate> eventTable = new();
    
    public static void AddListener(string eventType, Action handler)
    {
        if (eventTable.TryGetValue(eventType, out var d))
            eventTable[eventType] = Delegate.Combine(d, handler);
        else
            eventTable[eventType] = handler;
    }
    
    public static void RemoveListener(string eventType, Action handler)
    {
        if (eventTable.TryGetValue(eventType, out var d))
        {
            d = Delegate.Remove(d, handler);
            if (d == null) eventTable.Remove(eventType);
            else eventTable[eventType] = d;
        }
    }
    
    public static void Broadcast(string eventType)
    {
        if (eventTable.TryGetValue(eventType, out var d))
            (d as Action)?.Invoke();
    }
}
```

### 常见内存泄漏场景
```csharp
// 泄漏：敌人死亡销毁，但 Enemy.OnDeath 事件仍被成就系统持有
void Start() {
    EventCenter.AddListener("EnemyKilled", OnEnemyKilled);
}
// 必须：
void OnDestroy() {
    EventCenter.RemoveListener("EnemyKilled", OnEnemyKilled);
}
```

## 💬 面试官常见追问
- **UnityEvent 为什么比 Csharp event 慢？** → UnityEvent 内部使用反射调用方法，且有序列化/反序列化开销
- **事件中心用 string 做 key 有什么问题？** → 字符串比较慢，拼写错误编译器不报错；改进：用 enum 或 int ID
- **怎么避免事件造成的内存泄漏？** → 使用弱引用（WeakReference）、在 OnDestroy 强制注销、场景切换时清空事件表

## ⚠️ 我曾经的误区 / 网上常见错答
- 误区：事件系统就是全局变量。设计良好的事件系统通过松耦合减少模块依赖，并非全局变量的反面教材
- 误区：事件回调里注销当前事件没问题。可能导致迭代器异常，应延迟处理或复制事件列表
