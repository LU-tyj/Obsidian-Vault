## 一句话结论（自测用）
> vector = 动态数组（连续内存，2倍扩容），list = 双向链表，map = 红黑树（有序 O(logN)），unordered_map = 哈希表（无序 O(1)）。游戏开发高频查找用 unordered_map，需要排序遍历用 map。

## 标准答案（结构化、可背诵，2分钟内讲完）
1. **vector**：动态数组，内存连续，支持随机访问 O(1)。扩容时重新分配一块更大的内存（通常 1.5~2 倍），拷贝/移动旧元素，释放旧内存。`reserve()` 预分配避免多次扩容。
2. **list**：双向循环链表，内存不连续。插入/删除 O(1)，随机访问 O(n)。不需要扩容，迭代器不会因其他元素插入/删除而失效。
3. **deque**：分段连续内存（中控器 + 多个缓冲区）。支持两端高效插入/删除 O(1)，随机访问 O(1)（比 vector 稍慢）。
4. **map**：红黑树，键有序，插入/查找/删除 O(logN)。节点含 color 标记 + 左右子 + 父指针。红黑树用非严格平衡换更少旋转次数。
5. **unordered_map**：哈希表（数组 + 链表/红黑树），平均 O(1)，冲突时退化 O(n)。负载因子超过阈值（默认 1.0）触发 rehash，桶数量翻倍。

## 详细解析

### vector 扩容细节
- VS 下通常 1.5 倍扩容，GCC 下通常 2 倍扩容
- 扩容导致**所有迭代器失效**（内存重新分配）
- `push_back` vs `emplace_back`：前者先构造再拷贝/移动，后者直接在容器内存中就地构造（减少一次拷贝）
- `reserve(n)` 只分配内存不构造对象；`resize(n)` 分配内存并构造 n 个元素

### vector 迭代器失效场景
| 操作 | 是否失效 |
|------|---------|
| push_back 且需要扩容 | 全部失效 |
| push_back 不需要扩容 | end() 失效 |
| insert 任何位置 | 插入位置及之后全部失效 |
| erase 任何位置 | 删除位置及之后全部失效 |

### map vs unordered_map 选型
| 场景 | 选择 |
|------|------|
| 需要排序遍历 | map |
| 高频查找（不关心顺序） | unordered_map |
| 内存敏感 | map（unordered_map 哈希表有额外内存开销） |
| 需要稳定迭代器 | map（节点不移动） |

## 面试官常见追问
- vector 为什么是 1.5 倍或 2 倍扩容？（2 倍便于内存对齐和位运算；1.5 倍利于复用释放的内存块）
- map 为什么用红黑树不用 AVL？（红黑树旋转次数少，插入/删除更高效；AVL 严格平衡，查找略优但插入更慢）
- unordered_map 的哈希冲突怎么解决？（链地址法：冲突元素放在同一个桶的链表中；Java 中冲突超过 8 个会转红黑树）
- 自定义类型做 map 的 key 需要什么？（重载 `operator<`，或提供自定义比较器）

## 我曾经的误区 / 网上常见错答
- **错**："vector 每次扩容都是 2 倍" —— 不同编译器实现不同，MSVC 是 1.5 倍
- **错**："list 在任何位置插入删除都是 O(1)" —— 需要先找到位置（遍历 O(n)），找到后插入才是 O(1)
- **错**："unordered_map 的查找一定是 O(1)" —— 哈希冲突严重时退化到 O(n)
