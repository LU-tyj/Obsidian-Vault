## 🎯 一句话结论（自测用）
> BFS 无权最短路径，Dijkstra 加权最短路径（贪心），A* = Dijkstra + 启发式函数（曼哈顿/欧几里得距离），游戏寻路首选 A*。

## ✅ 标准答案（结构化、可背诵，2分钟内讲完）
1. **BFS**：队列 + 层序遍历，无权图最短路径。时间复杂度 O(V+E)
2. **DFS**：栈/递归，"一路走到黑"。适合连通性判断、拓扑排序、回溯
3. **Dijkstra**：优先队列 + 贪心，每次选距离最小的未访问节点。O(ElogV)
4. **A***：核心公式 `F = G + H`。G = 起点到当前实际距离，H = 启发式估计（曼哈顿/欧几里得距离）。H 必须可接受（admissible，不高估），否则不一定最优
5. **动态障碍**：从当前位置重新 A*、局部路径修正、分层寻路

## 🔍 详细解析

### BFS vs DFS vs Dijkstra vs A* 对比
| 算法 | 数据结构 | 特点 | 最优性 | 适用场景 |
|------|---------|------|--------|---------|
| BFS | 队列 | 按层遍历 | 无权图最短路径 | 迷宫、社交网络 |
| DFS | 栈/递归 | 一路到底 | 不一定最优 | 连通性、拓扑排序 |
| Dijkstra | 优先队列 | 每次选最短距离 | 加权图最短路径 | 地图导航 |
| A* | 优先队列(F值) | 启发式引导方向 | 启发式可接受时最优 | 游戏寻路 |

### A* 算法完整流程
```
1. 起点放入 Open List
2. 取 Open List 中 F 值最小的节点 -> 移入 Closed List
3. 检查该节点是否为终点 -> 是则回溯路径结束
4. 遍历周围可行走节点：
   - 已在 Closed List 或障碍 -> 跳过
   - 不在 Open List -> 加入，计算 F=G+H，设父节点
   - 已在 Open List -> 若新 G 更小则更新 F 和父节点
5. 重复 2-4 直到找到终点或 Open List 为空
6. 从终点沿父节点回溯得到路径
```

### A* 数据结构优化
- Open List 用最小堆/优先队列管理
- Closed List 用哈希表加速查找

### NavMesh vs A*
- **NavMesh**：Unity 内置，基于多边形网格，适合复杂 3D 地形
- **A***：基于栅格，可自定义实现，适合 2D/网格地图
- 面试追问"如果场景是 3D 开放世界怎么寻路" -> 先用 NavMesh 生成可行走区域，再在 NavMesh 上用 A*

### 游戏场景应用题：炸弹爆炸范围判断
场景中大量怪物，炸弹爆炸如何判断哪些怪物在范围内？
- 四叉树/八叉树空间分区缩小搜索范围
- 距离平方比较（避免开根号）
- Job System 多线程并行

## 💬 面试官常见追问
- "A* 的启发式函数怎么选？" -> 网格地图用曼哈顿距离（4方向移动）或欧几里得距离（8方向）。H 不能高估实际距离
- "Open List 满了怎么办？" -> 不可达区域太多，检查地图连通性。可用双向 BFS/A* 加速
- "动态障碍物怎么处理？" -> 局部重规划（D* Lite / 重新 A*）

## ⚠️ 我曾经的误区 / 网上常见错答
- **误区**：A* 一定能找到最短路径。H 必须 admissible（不高估）才保证最优
- **误区**：Dijkstra 是 BFS 的变体。Dijkstra 处理加权图，BFS 只能处理无权图
- **误区**：只知道 A* 的 F=G+H，说不清 Open/Closed List 的具体流程
