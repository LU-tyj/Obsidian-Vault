## 一句话结论（自测用）
> 浅拷贝 = 逐成员复制（包括指针地址），导致两个对象共享同一块堆内存（double free 隐患）；深拷贝 = 复制指针指向的实际数据到新内存，两个对象完全独立。含堆资源（指针/文件句柄）的类必须自定义拷贝构造/赋值实现深拷贝。

## 标准答案（结构化、可背诵，2分钟内讲完）
1. **浅拷贝**：编译器默认生成的拷贝构造函数是浅拷贝。将所有成员逐位复制，对于指针只复制地址值，导致两个对象的指针成员指向同一块内存。析构时同一块内存被释放两次 → double free / 悬垂指针。
2. **深拷贝**：自定义拷贝构造函数，对指针成员分配新内存并复制指向的内容。两个对象拥有独立的内存副本，互不影响。
3. **拷贝构造函数 vs 拷贝赋值运算符**：
   - 拷贝构造：从无到有创建一个新对象。`MyClass obj2 = obj1;`
   - 拷贝赋值：已存在的对象被赋予新值。需先释放旧资源。`obj2 = obj1;`
4. **现代 C++ 推荐做法**：用 RAII 容器（`std::vector`、`std::string`）替代裸指针，它们的拷贝构造已正确实现深拷贝，无需手动管理。

## 详细解析

### 深拷贝实现模板
```cpp
class MyArray {
    int* data;
    size_t size;
public:
    // 拷贝构造函数 — 深拷贝
    MyArray(const MyArray& other)
        : data(new int[other.size]), size(other.size) {
        std::copy(other.data, other.data + size, data);
    }
    // 拷贝赋值 — 注意自赋值、释放旧资源
    MyArray& operator=(const MyArray& other) {
        if (this != &other) {           // 防止自赋值
            delete[] data;              // 释放旧资源
            size = other.size;
            data = new int[size];
            std::copy(other.data, other.data + size, data);
        }
        return *this;
    }
};
```

### 拷贝构造的调用时机
- `MyClass obj2 = obj1;` — 直接初始化
- `MyClass obj2(obj1);` — 直接初始化
- 函数参数按值传递 — 传参时调用拷贝构造
- 函数按值返回 — 可能触发拷贝（但编译器会做 RVO 优化）

## 面试官常见追问
- 什么情况下默认生成的拷贝构造就够了？（所有成员都是值类型或已正确实现深拷贝的 RAII 类型时）
- 拷贝赋值为什么需要检查自赋值？（`obj = obj;` 时如果先释放再分配，会丢失数据甚至崩溃）
- 浅拷贝一定不好吗？（不需要独占资源时可以——如多个对象共享只读数据；此时可用 shared_ptr 显式表达意图）

## 我曾经的误区 / 网上常见错答
- **错**："默认拷贝构造总是浅拷贝" —— 对 RAII 类型成员会调用其拷贝构造（正确的深拷贝），裸指针才是浅拷贝
- **错**："写好了拷贝构造就不需要拷贝赋值了" —— 两者独立，不写编译器各自生成（可能导致行为不一致）
- **错**："C++11 之后用移动代替深拷贝就行" —— 移动是"窃取"不是复制；需要独立副本时必须深拷贝
