## 🎯 一句话结论（自测用）
> Mipmap 是纹理的 LOD——预先生成分辨率逐级减半的多级纹理副本。远处物体自动使用低分辨率 Mip 级，优化显存带宽并减少锯齿（Moire 纹）。代价是额外约 33% 内存占用。UI 不使用 Mipmap。

## ✅ 标准答案（结构化、可背诵，2分钟内讲完）
1. **Mipmap 的定义**：预先生成纹理的多级分辨率副本，每级长宽减半。例如 1024x1024 纹理会有 1024、512、256、...、1 共 11 级
2. **工作原理**：渲染时 GPU 根据片元在屏幕上的覆盖面积自动选择最合适的 Mip 级——覆盖面积小（远处）用高级（小分辨率），覆盖面积大（近处）用低级（原分辨率）
3. **优点**：
   - 减少纹理缓存（Texture Cache）未命中率，大幅降低显存带宽消耗
   - 减少远距离纹理的锯齿（Moire 纹）
4. **缺点**：所有 Mip 级加起来约占用原始纹理的 133% 内存（1 + 1/4 + 1/16 + ... ≈ 1.33）
5. **三线性过滤**：在两个相邻的 Mip 级别之间再做一次线性插值，让 Mip 切换更平滑
6. **各向异性过滤**：当纹理以倾斜角度渲染时（如地面纹理远望），普通 Mipmapping 会过度模糊。各向异性过滤沿多个方向采样，保持纹理清晰。额外内存开销很小，但采样次数增加

## 🔍 详细解析

**为什么 UI 不使用 Mipmap？**
- UI 通常在屏幕上以接近 1:1 的像素比渲染，永远使用 Mip 0 级
- Mipmap 在 UI 上没有性能或质量收益，只会浪费 33% 内存
- 对于 UI 图集，关闭 Generate Mip Maps 可以显著节省内存

**Mipmap 与 LOD 的类比**：
- Mipmap：纹理的多级精度版本，基于屏幕占比自动切换
- LOD：模型的多级精度版本，基于距离手动切换
- 两者都是"远小近大"的性能优化思想

## 💬 面试官常见追问
- "如果不使用 Mipmap，远处纹理会怎样？" -> 产生 Moire 纹/闪烁：远处的纹理细节密度远高于像素密度，采样时多个纹素映射到同一像素，产生不对齐的伪影
- "三线性过滤和各向异性过滤的区别？" -> 三线性解决 Mip 级别间的过渡，各向异性解决倾斜视角下的模糊。两者解决不同的问题，通常同时使用

## ⚠️ 我曾经的误区 / 网上常见错答
- 误区：Mipmap 让纹理更清晰。实际上 Mipmap 让远处纹理"适度模糊"从而避免更糟糕的 Moire 纹/锯齿
- 误区：Mipmap 占用 2 倍内存。每个 Mip 级面积是上一级的 1/4，无穷级数求和为 1 + 1/4 + 1/16 + ... = 4/3，即多了约 33%
