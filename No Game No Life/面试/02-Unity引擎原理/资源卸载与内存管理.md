## 一句话结论（自测用）
> 资源卸载三层级：Unload(true) 卸载 Bundle + 所有资源（风险）、Unload(false) 仅卸载压缩数据（保留资源）、Resources.UnloadUnusedAssets() 全局清理引用计数为 0 的资源。Addressables 用引用计数自动管理。

## 标准答案（结构化、可背诵，2分钟内讲完）
1. **AssetBundle 卸载**：
   - `Unload(true)`：卸载 Bundle 包体 + **所有已加载资源**。引用丢失风险，场景切换用。
   - `Unload(false)`：只卸载 Bundle 的压缩数据，已加载的资源**保留**在内存。局部卸载用。
   - 错误使用 `Unload(true)` 的后果：正在使用的资源变成 MissingReference（紫色/透明物体）
2. **Resources 卸载**：
   - `Resources.UnloadAsset(obj)`：卸载特定资源
   - `Resources.UnloadUnusedAssets()`：全局清理所有引用计数为 0 的资源（**耗时操作**，场景切换时调用）
   - 对比：AssetBundle 按包粒度卸载 = 控制力强；Resources 只能全局 = 难以精细控制
3. **Addressables 卸载**：
   - `Addressables.Release(handle)`：减少引用计数
   - `Addressables.ReleaseInstance(instanceHandle)`：销毁实例 + 减引用计数
   - 引用计数归零时，该资源可被 `UnloadUnusedAssets` 清理
4. **检测是否卸载干净**：
   - Unity Profiler -> Memory 面板
   - Memory Profiler 包查看引用链
   - 检查所有引用：组件字段、静态变量、事件委托、协程持有

## 详细解析

### 资源占用的三部分内存
| 内存类型 | 说明 | 卸载方式 |
|---------|------|---------|
| Bundle 压缩数据 | 从文件读取的压缩包本体 | Unload(false) |
| 序列化文件头 | Asset 的元数据索引（很小的字典） | Unload(true) |
| 实际 Asset 对象 | 纹理/模型/音频的解压数据（占用最大） | Unload(true) 或 UnloadUnusedAssets |

### 场景切换时的标准卸载流程
```csharp
// 1. 卸载所有该场景的 AssetBundle（保留其他场景共用资源）
foreach (var bundle in sceneBundles) {
    bundle.Unload(false); // 只卸载压缩数据
}
// 2. 全局清理
Resources.UnloadUnusedAssets();
// 3. 可选：手动触发 GC
System.GC.Collect();
```

### 常见内存泄漏原因
1. **静态变量持有引用**：GC 无法回收被 static 字段引用的对象
2. **事件/委托未注销**：发布者持有订阅者引用，订阅者无法被 GC
3. **协程未停止**：运行中的协程持有对象引用
4. **单例模式持有已销毁对象的引用**：使用 `WeakReference` 或手动清理
5. **AssetBundle.Unload(false) 后资源常驻**：已加载的资源不会随着 Bundle 卸载而释放

## 面试官常见追问
- `UnloadUnusedAssets` 为什么耗时？（需要遍历所有 Managed Object 检查引用计数，可能耗时几百毫秒）
- 怎么判断一个纹理是否被真正释放了？（Memory Profiler 中查看，或 Profiler.BeginSample 比较前后内存）
- Addressables 的引用计数什么时候会出错？（同一个 Asset 被多次加载且 Release 次数不匹配）
