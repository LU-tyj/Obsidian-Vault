_Avoid unnecessary work by deferring it until the result is needed._

## 1 Motivation
当一群树状结构的物体进行改变时，比如物体节点的渲染，如果改变根节点的位置，那么普通情况下就直接从父物体计算，然后对子物体的现实坐标四元数运算，然后再到下一个子物体，然后再对其子物体进行计算。这样会造成了 $n^2$ 的计算。

我们可以通过延迟重算的方法，来将局部的修改（手中武器的相对位置）和更新世界变换（武器在世界坐标中的位置）解耦。我们不像上面所说的那样，每进行一个世界坐标变换，就要遍历 $\times2$ 子节点。我们先进行局部修改，再最后计算一次世界变换。

为了实现这个目标，我们要对图中的每个小物体添加一个“flag”，存储两种状态：`set` & `cleared`（其实就是true & false）。当我们需要这个物体的世界变换时，我们检查这个flag，如果“set”，那么计算这个世界变换，然后把flag设为“cleared”。

- 它将父链上物体的多个局部变换的改动分解为每个物体的一次重计算。
- 它避免了没有移动的物体的重计算。
- 一个额外的好处：如果一个物体在渲染之前移除了，那就根本不用计算它的世界变换。
其实就是渲染时统一运算，dirty只是打上标记

脏标记模式：一组原始数据随时间变化。一组衍生数据经过一些代价昂贵的操作由这些数据确定。一个脏标记跟踪这个衍生数据是否和原始数据同步。它在原始数据改变时被设置。如果它被设置了，那么当需要衍生数据时，它们就会被重新计算并且标记被清除。否则就使用缓存的数据。

主要应用在保存等，记录物体是否发生了变化，而不是对所有的物体都来一遍。

---

## 2 When & How to use it
当原始数据的修改比使用数据多时，这个模式比较合适，就像上面的渲染的例子。

但延时处理也可能出现卡顿的问题，而且如果某个东西出错就可能完全无法工作（编辑器在计算机被动关机时可能出现保存不了文档）

必须保证每次状态改动都设置脏标记（缓存失效问题）。

必须在内存中保存上次的衍生数据。

## 3 Sample
我们先写出矩阵变化。
```cpp
class Transform
{
public:
  static Transform origin();

  Transform combine(Transform& other);
};
```
>`combine` 可以组合父链中的所有局部变换得到自己的世界变换

定义场景图中的物体类
```cpp
class GraphNode
{
public:
  GraphNode(Mesh* mesh)
  : mesh_(mesh),
    local_(Transform::origin())
    dirty_(true)
  {}

private:
  Transform local_;
  Mesh* mesh_;

  GraphNode* children_[MAX_CHILDREN];
  int numChildren_;
  
  Transform world_;
  bool dirty_;
};
```
>`world_` 缓存了上次计算的世界变换，我们使用`void renderMesh(Mesh* mesh, Transform transform)` 来渲染每个节点的图原

普通的遍历是这样的：
```cpp
void GraphNode::render(Transform parentWorld)
{
  Transform world = local_.combine(parentWorld); // 由父链和局部坐标计算世界坐标

  if (mesh_) renderMesh(mesh_, world);

  for (int i = 0; i < numChildren_; i++)
  {
    children_[i]->render(world);
  }
}
```
>然后使用 `graph_ -> render(Transform::origin())` 从根节点进行渲染

使用 dirty flag后，就变成了这样：
```cpp
void GraphNode::render(Transform parentWorld, bool dirty)
{
  dirty |= dirty_;
  if (dirty)
  {
    world_ = local_.combine(parentWorld);
    dirty_ = false;
  }

  if (mesh_) renderMesh(mesh_, world_);

  for (int i = 0; i < numChildren_; i++)
  {
    children_[i]->render(world_, dirty);
  }
}
```
>如果不是dirty的话，就跳过 `combine()`，使用现存的世界坐标来进行渲染。
>当有子类时，自己设为dirty，那么子类都设为dirty

## 4 Design Patterns
### 4.1 何时清除脏标记？
就如上例中，当我们可以在使用计算后清楚脏标记。
也可以在检查点，比如游戏存档，在自由活动时才允许或者自动存档。
在后台，启动一个固定的计时器。
