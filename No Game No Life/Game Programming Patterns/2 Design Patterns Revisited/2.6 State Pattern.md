## 1 有限状态机（finite state machines，FSM）
### 1.1 Introduction
- **你拥有一组状态**，并且可以在这组状态之间进行切换。比如：站立、跳跃、躲避和俯冲。
- 状态机**同一时刻只能处于一种状态**。女主角无法同时跳跃和站立。事实上，防止同时存在两个状态是我们使用有限状态机的原因。
- 状态机会**接收一组输入或者事件**。在我们这个例子中，它们就是按钮的按下和释放。
- **每一个状态有一组转换**，每一个转换都关联着一个输入并指向另一个状态。当有一个输入进来的时候，如果输入与当前状态的其中一个转换匹配上，则状态机便会转换状态到输入事件所指的状态。
整个状态及可以分为：状态、输入、转换

### 1.2 Example
最简单的代码实现是通过 `enum` 进行枚举，然后使用 `switch case` 进行状态的输入和转换。
而状态模式是定一个一个接口，再给每一个状态定义一个类。例子如下：

1. A state interface. 包含两个虚函数 `handleInput` 和 `update`
```cpp
class HeroineState
{
public:
  virtual ~HeroineState() {}
  virtual void handleInput(Heroine& heroine, Input input) {}
  virtual void update(Heroine& heroine) {}
};
```

2. Classes for each state.
```cpp
class DuckingState : public HeroineState
{
public:
  DuckingState()
  : chargeTime_(0)
  {}

  virtual void handleInput(Heroine& heroine, Input input) {
    if (input == RELEASE_DOWN)
    {
      // Change to standing state...
      heroine.setGraphics(IMAGE_STAND);
    }
  }

  virtual void update(Heroine& heroine) {
    chargeTime_++;
    if (chargeTime_ > MAX_CHARGE)
    {
      heroine.superBomb(); // 蓄力成功
    }
  }

private:
  int chargeTime_; // 蹲下蓄力需要的时间
};
```

3. Delegate to the state.
现在给我们的主角一个指向状态的指针 `state`，让她来发号施令，委托状态进行
```cpp
class Heroine
{
public:
  virtual void handleInput(Input input)
  {
    state_->handleInput(*this, input);
  }

  virtual void update()
  {
    state_->update(*this);
  }

  // Other methods...
private:
  HeroineState* state_;
};
```

### 1.3 状态对象应该放在哪里呢
“我这里忽略了一些细节。为了修改一个状态，我们需要给state_指针赋值为一个新的状态，**但是这个新的状态对象要从哪里来呢**？我们之前的枚举方法是定义一些数字。但是，现在我们的状态是类，我们需要获取这些类的实例。通常来说，有两种实现方法。”

#### 1.3.1 Static States
如果一个状态对象没有任何数据成员，那么它的唯一数据成员便是虚表指针了。那样的话，我们就没有必要创建此状态的多个实例了，因为它们的每一个实例都是相同的。
>没有任何数据成员指的是：内部只有函数，但没有属性。这样的话创建多个实例其实都是指向同一个虚函数的指针

  在那种情况下，我们可以定义一个静态实例。即使你有一系列的FSM在同时运转，所有的状态机也能同时指向这一个唯一的实例。
  >享元模式
  
可以把这些实例放在基类中
```cpp
class HeroineState
{
public:
  static StandingState standing;
  static DuckingState ducking;
  static JumpingState jumping;
  static DivingState diving;

  // Other code...
};
```

在 `JumpState` 中，就可以这样实现
```cpp
if (input == PRESS_B)
{
  heroine.state_ = &HeroineState::jumping;
  heroine.setGraphics(IMAGE_JUMP);
}
```

#### 1.3.2 Instantiated States
静态状态在有一个属性以及多人游戏的情况下无法使用，这时候就要动态地创建一个状态实例，我们此时也要负责**清理老的状态实例**。

我们也可以选择在`HeroineState`类中的`handleInput()`方法里面可选地返回一个新的状态。当这个状态返回的时候，主角将会删除老的状态并切换到这个新的状态，如下所示：
```cpp
void Heroine::handleInput(Input input)
{
  HeroineState* state = state_->handleInput(*this, input);
  if (state != NULL)
  {
    delete state_;
    state_ = state;
  }
}
```

这时候状态的转换可以返回一个新的实例
```cpp
HeroineState* StandingState::handleInput(Heroine& heroine,
                                         Input input)
{
  if (input == PRESS_DOWN)
  {
    // Other code...
    return new DuckingState();
  }

  // Stay in this state.
  return NULL;
}
```

### 1.4 进入和退出状态
当主角更改状态的时候，我们也会切换它的贴图。现在，这段代码包含在它要切换的状态的上一个状态里面。当她从躲避状态切换到站立状态时，躲避状态将会修改它的图像：
```cpp
HeroineState* DuckingState::handleInput(Heroine& heroine,
                                        Input input)
{
  if (input == RELEASE_DOWN)
  {
    heroine.setGraphics(IMAGE_STAND);
    return new StandingState();
  }

  // Other code...
}
```

我们想要的是这两者能分离出来，使得 `StandingState` 自己管理自己的 Image，可以使用 `enter()` 和 `exit()` 来进行简化
```cpp
class StandingState : public HeroineState
{
public:
  virtual void enter(Heroine& heroine)
  {
    heroine.setGraphics(IMAGE_STAND);
  }

  // Other code...
};
```

```cpp
void Heroine::handleInput(Input input)
{
  HeroineState* state = state_->handleInput(*this, input);
  if (state != NULL)
  {
    delete state_;
    state_ = state;

    // Call the enter action on the new state.
    state_->enter(*this);
  }
}
```
>这样就不用在躲避状态下改变图片。

## 2 Concurrent State Machines 并发状态机
如果给我们的主角一个持武器的功能，那么按照上面的设计，我们有n个普通状态和m个武器就会多产生n * m 个状态。这里出现的问题是我们把两种不同类型的状态硬塞到同一个状态机里面去了，解决方法很直观，就是写两个状态机。

```cpp
class Heroine
{
  // Other code...

private:
  HeroineState* state_;
  HeroineState* equipment_;
};
```

在处理输入时，需要给两个状态机都发送委托。
```cpp
void Heroine::handleInput(Input input) 
{   
	state_->handleInput(*this, input);   
	equipment_->handleInput(*this, input); 
}
```

## 3 Hierarchical State Machines 层次状态机
举个例子，可以写个 `onGround` 状态，然后让其他的状态继承。
```cpp
class OnGroundState : public HeroineState
{
public:
  virtual void handleInput(Heroine& heroine, Input input)
  {
    if (input == PRESS_B)
    {
      // Jump...
    }
    else if (input == PRESS_DOWN)
    {
      // Duck...
    }
  }
};
```

```cpp
class DuckingState : public OnGroundState
{
public:
  virtual void handleInput(Heroine& heroine, Input input)
  {
    if (input == RELEASE_DOWN)
    {
      // Stand up...
    }
    else
    {
      // Didn't handle input, so walk up hierarchy.
      OnGroundState::handleInput(heroine, input);
    }
  }
};
```

"你可以在基类中使用状态栈而不是单单一个状态的方法来更加明确地表示父状态的状态链。

我们当前的状态总是处于栈顶，栈顶下面的第一个元素是它的父状态，再下一个状态则是它的父状态的父状态，以此类推。如果你要进行一些与状态相关的行为操作，那么首先从栈顶状态开始。如果它不处理，则往下寻找直到找到一个能处理此事件的状态为止（如果找遍整个栈了，还是没能被处理，则将此事件被忽略掉）。"

## 4 Pushdown Automata 下推自动机
解决的是有限状态机没有历史记录的问题。比如p3r中神通法动画触发之后，角色要回到之前的状态（这个例子不是很恰当但是差不多意思）。

本来，有限状态机有一个指向当前状态的指针。而下推自动机则有一个状态栈。在一个有限状态机里面，当有一个状态切进来时，则替换掉之前的状态。下推自动机可以让你这样做，同时它还提供其他选择：  
- **你可以把这个新的状态放入栈里面**。当前的状态永远存在栈顶，所以你总能转换到当前状态。但是当前状态会将前一个状态压在栈中自身的下面而不是抛弃掉它。
- **你可以弹出栈顶的状态，该状态将被抛弃**。与此同时，上一个状态就变成了新的栈顶状态了。
