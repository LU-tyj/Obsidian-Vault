_Improve performance and memory use by reusing objects from a fixed pool instead of allocating and freeing them individually._

## 1 Motivation
我们程序造成内存碎片化会带来很多的问题，会造成连续内存往往非常小。如下图所示，当你打到关卡结束，结果boss加载不出来了。
![[Memory.png]]

因此我们直接支配一大块内存，知道游戏结束再进行释放，从而解决这个问题。

**对象池模式**：
“定义一个保持着可重用对象集合的对象池类。其中的每个对象支持对其“使用（in use）”状态的访问，以确定这一对象目前是否“存活（alive）”。在对象池初始化时，它预先创建整个对象的集合（通常为一块连续堆区域），并将它们都置为“未使用（not in use）”状态。

  当你想要创建一个新对象时就向对象池请求。它将搜索到一个可用的对象，将其初始化为“使用中（in use）”状态并返回给你。当该对象不再被使用时，它将被置回“未使用（not in use）”状态。使用该方法，对象便可以在无需进行内存或其他资源分配的情况下进行任意的创建和销毁。”

---

## 2 When & How to use it
最常见的比如[[Lec12 Effects]]中提及的例子系统，这么多粒子的生命周期难以一一管理，又需要频繁地创建和销毁，这时候就是对象池模式的好机会。
- 当你需要频繁地创建和销毁对象时
- 对象大小一致时
- 在堆上进行对象生成会出现内存分配慢或者产生内存碎片时
- 每个对象封装着获取代价昂贵且可重用的资源时，比如数据库、网络连接

但要注意这个模式也会带来很多问题。
1. **可能会有闲置的对象浪费内存**
2. **任意时刻处于存货状态的对象数目恒定**
	你不能重复申请一个正在使用的对象，因为他的属性都写在那里了。
	你可以不创造对象、强行清理现存对象、扩容对象池
3. **每个对象的内存大小固定**
4. **重用对象不会自动清理**
	这就需要我们注意，我们需要初始化对象而不仅仅是拿出来。因为对象一般会留有上一次使用时的数据。

---

## 3 Sample
我们以粒子系统为例。普通的实现就是给粒子一个是否被使用的状态属性，然后粒子可以每帧使用`animate()`更新动画。然后粒子池就是存储了所有粒子，然后每帧会遍历数组中的粒子，如果有使用中的粒子就创建出来，以及遍历调用其`animate()`方法，

这样就可以实现一个简单的对象池，但如果粒子数量过多，创建新粒子数量会十分缓慢。因为他要判断每个粒子是否可用，然后一个一个过去。因此我们这里说一个高级的空闲表。

1. Particle 类
```cpp
class Particle
{
public:
  Particle()
  : framesLeft_(0)
  {}

  void init(double x, double y,
            double xVel, double yVel, int lifetime)
  {
    x_ = x; y_ = y;
    xVel_ = xVel; yVel_ = yVel;
    framesLeft_ = lifetime;
  }

  void animate();

  bool inUse() const { return framesLeft_ > 0; }

  Particle* getNext() const { return state_.next; }
  void setNext(Particle* next) { state_.next = next; }

private:
  int framesLeft_;

  union
  {
    // State when it's in use.
    struct
    {
      double x, y;
      double xVel, yVel;
    } live;

    // State when it's available.
    Particle* next;
  } state_;
};
```
>`frameLeft_`表示是否使用，union中的成员`next`是指向下一个可用粒子的指针。
>这里使用了`union`，可以共享一块内存。并且用`struct`把我们Particle类使用时的属性包在一起，有种[[6.1 Data Locality]]中的感觉。

2. 对象池的实现，我们需要时刻跟踪列表的头指针，需要确保正确地初始化指针以及在创建和销毁粒子时保持住指针。
```cpp
class ParticlePool
{
public:
  void create(double x, double y,
              double xVel, double yVel, int lifetime);

  void animate();

private:
  Particle* firstAvailable_;

  static const int POOL_SIZE = 100;
  Particle particles_[POOL_SIZE];
};
```
>`firstAvailable_`就是列表的头指针

构造函数如下（对所有粒子进行可用初始化）：
```cpp
ParticlePool::ParticlePool()
{
  // The first one is available.
  firstAvailable_ = &particles_[0];

  // Each particle points to the next.
  for (int i = 0; i < POOL_SIZE - 1; i++)
  {
    particles_[i].setNext(&particles_[i + 1]);
  }

  // The last one terminates the list.
  particles_[POOL_SIZE - 1].setNext(NULL);
}
```
>讲所有粒子的下一个可用粒子指向一下个粒子（挺绕口的）

3. `create()` 以及 `animate()` 函数的修改
```cpp
void ParticlePool::create(double x, double y,
                          double xVel, double yVel,
                          int lifetime)
{
  // Make sure the pool isn't full.
  assert(firstAvailable_ != NULL);

  // Remove it from the available list.
  Particle* newParticle = firstAvailable_;
  firstAvailable_ = newParticle->getNext();

  newParticle->init(x, y, xVel, yVel, lifetime);
}
```
>这里是取得下一个可用指针，然后初始化一个粒子。将头指针指向新的可用粒子

```cpp
// 这是粒子的新的animate方法
bool Particle::animate()
{
  if (!inUse()) return false;

  framesLeft_--;
  x_ += xVel_;
  y_ += yVel_;

  return framesLeft_ == 0;
}
```
>这里当存活的粒子在最后一帧死掉时函数返回`true`

当粒子死掉后，我们将其添加回空闲表：
```cpp
void ParticlePool::animate()
{
  for (int i = 0; i < POOL_SIZE; i++)
  {
    if (particles_[i].animate())
    {
      // Add this particle to the front of the list.
      particles_[i].setNext(firstAvailable_);
      firstAvailable_ = &particles_[i];
    }
  }
}
```
>如果死了，那么把他设为头指针，把原本头指针的位置设置为下一个生成的粒子
