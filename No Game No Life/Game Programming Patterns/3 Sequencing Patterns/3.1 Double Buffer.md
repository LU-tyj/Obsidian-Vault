## 1 Introduction
双缓冲的目的是解决渲染有顺序、不同步的问题，使物体能一次性显示出来。

显示器是通过读取 framebuffer中的每个数据，来显示在屏幕上。如果就是普通的读取显示，可能会出现读取和显示同步进行的后果，导致会出现频闪等错误。因此使用双缓冲机制来进行数据的读取和写入分离。
>文章举了一个舞台表演的例子：“我们建立两个舞台以便它们都能为观众所见。它们各有各的一套灯光。我们称其为A舞台和B舞台。场景1正在A舞台上上演，同时舞台B正处在黑暗中并正由场景后台进行着场景2的准备。一旦场景1结束，我们就关掉A舞台的灯光并将灯光转移到B舞台，观众们便立即聚焦到新舞台并看到了第二幕场景上映。”
>每次场景切换通过灯光的转换来改变，这样就能看到完整的表演。

在游戏渲染中，我们用一个current buffer显示，一个next buffer写入，当current buffer显示完毕，会把current buffer和next buffer互换，实现无缝衔接。

**使用情境**：
- 我们需要维护一些被逐步改变着的状态量。
- 同个状态可能会在其被修改的同时被访问到。
- 我们希望避免访问状态的代码能看到具体的工作过程。
- 我们希望能够读取状态但不希望等待写入操作的完成。

注意交换本身需要消耗时间，以及会对内存进行占用。

## 2 Examples
### 2.1 Scene
需要场景的图像一次性显示，画图的流程就为：清空 `next_` -> 在`next_`中画图 -> `swap`
```cpp
class Scene
{
public:
	Scene()
	: current_(&buffer[0]), next_(&buffer[1])
	{}
	
	void draw()
	{
		next_->clear();
		
	    next_->draw(1, 1);
	    // ...
	    next_->draw(4, 3);
	
	    swap();
	}
	
	FrameBuffer& getBuffer { return *current_; }

private:
	void swap()
	{
		FrameBuffer* tmp = current_;
		current_ = next_;
		next_ = tmp;
	}
	
	FrameBuffer buffer[2];
	FrameBuffer* current_;
	FrameBuffer* next_;
}
```

```cpp
class Framebuffer
{
public:
  Framebuffer() { clear(); }

  void clear()
  {
    for (int i = 0; i < WIDTH * HEIGHT; i++)
    {
      pixels_[i] = WHITE;
    }
  }

  void draw(int x, int y)
  {
    pixels_[(WIDTH * y) + x] = BLACK;
  }

  const char* getPixels()
  {
    return pixels_;
  }

private:
  static const int WIDTH = 160;
  static const int HEIGHT = 120;

  char pixels_[WIDTH * HEIGHT];
};
```

### 2.2 Not Just For Graphic
演员的打巴掌比赛，其中被打了会打回去。这时候就会出现读写的问题（比如第一个人没动手，所以输出什么也没干，但这之后第二个人打了第一个人，那么第一个人会打回去），这样子就能获得正确的状态

先准备一个表演的平台
```cpp
class Stage
{
public:
  void add(Actor* actor, int index)
  {
    actors_[index] = actor;
  }

  void update()
  {
    for (int i = 0; i < NUM_ACTORS; i++)
    {
      actors_[i]->update();
    }
	for (int i = 0; i < NUM_ACTORS; i++)
    {
      actors_[i]->swap();
    }    
  }

private:
  static const int NUM_ACTORS = 3;

  Actor* actors_[NUM_ACTORS];
};
```

演员基类
```cpp
class Actor
{
public:
  Actor() : currentSlapped_(false) {}

  virtual ~Actor() {}
  virtual void update() = 0;

  void swap()
  {
    // Swap the buffer.
    currentSlapped_ = nextSlapped_;

    // Clear the new "next" buffer.
    nextSlapped_ = false;
  }

  void slap()       { nextSlapped_ = true; }
  bool wasSlapped() { return currentSlapped_; }

private:
  bool currentSlapped_;
  bool nextSlapped_;
};
```

喜剧演员
```cpp
class Comedian : public Actor
{
public:
  void face(Actor* actor) { facing_ = actor; }

  virtual void update()
  {
    if (wasSlapped()) facing_->slap();
  }

private:
  Actor* facing_;
};
```

## 3 Design Decisions
- 交换两个buffer的指针
	方便简单，但如果buffer的指针为动态，即不能持久化指向的话，就无法实现
- 进行数据拷贝
	缺点很明显

**What is the granularity of the buffer?**
有两种：
1. 只有一对大 buffer，比如 Frame Buffer，这样只需要交换指针就好了
2. 有多对小 buffer，比如 Actor Buffer（上面的打巴掌，每个actor都有一个），这样需要遍历
	但这个可以修改成大buffer
```cpp
class Actor
{
public:
  static void init() { current_ = 0; }
  static void swap() { current_ = next(); } // 静态方法，会交换所有演员的

  void slap()        { slapped_[next()] = true; }
  bool wasSlapped()  { return slapped_[current_]; }

private:
  static int current_;
  static int next()  { return 1 - current_; }

  bool slapped_[2];
};
```
>演员们通过current_索引状态数组来访问其当前状态。下个状态总是数组中的另一个索引，故我们可以通过next()来获取它。此时交换状态只需变换current_的索引。聪明的地方在于swap()现在是一个静态方法——只需要调用一次，每个演员的状态都将会被交换。
