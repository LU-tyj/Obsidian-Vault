## 一句话结论（自测用）
> Unity 动画系统演进：Legacy Animation -> Mecanim (Animator + 状态机) -> PlayableGraph (可编程动画图)。AnimatorController 中的所有 AnimationClip 都会加载到内存，优化用 AnimatorOverrideController 按需替换。

## 标准答案（结构化、可背诵，2分钟内讲完）
1. **动画系统演变**：
   - **Legacy Animation**：旧版，已废弃。Play/Stop 简单控制，无状态机。
   - **Mecanim（主流）**：Animator + AnimatorController + 状态机。可视化编辑状态转换，支持 Blend Tree、IK、Layer 遮罩。
   - **PlayableGraph**：可编程的动画图 API，更灵活。可动态组合动画、混合、添加回调。Timeline 底层就是 PlayableGraph。
2. **AnimatorController 的核心要素**：
   - **State**：动画状态，绑定一个 AnimationClip（或 Blend Tree）
   - **Transition**：状态间的转换条件（基于 Parameters：Float/Int/Bool/Trigger）
   - **Layer**：动画分层（如上半身/下半身分开控制），通过 Avatar Mask 控制影响范围
   - **Parameter**：动画状态机参数，代码通过 `animator.SetFloat/SetBool/SetTrigger` 控制
3. **Blend Tree（混合树）**：
   - 1D Blend Tree：根据单一参数在多个动画间混合（如 speed: idle -> walk -> run）
   - 2D Blend Tree：两个参数（如 direction + speed）在动画间插值
4. **动画内存优化**：AnimatorController 引用的所有 AnimationClip 都会加载。优化：`AnimatorOverrideController` 按需替换动画，避免一次性加载所有。

## 详细解析

### AnimatorOverrideController 的使用
```csharp
// 原始 Controller（引用占位动画）
AnimatorOverrideController overrideController = 
    new AnimatorOverrideController(originalController);

// 运行时替换为实际动画
overrideController["IdlePlaceholder"] = loadedIdleClip;
overrideController["RunPlaceholder"] = loadedRunClip;

animator.runtimeAnimatorController = overrideController;
```
适用场景：不同角色共享同一套状态机逻辑，但使用不同的动画资源。

### PlayableGraph 的核心能力
```csharp
PlayableGraph graph = PlayableGraph.Create("MyGraph");
var output = AnimationPlayableOutput.Create(graph, "Output", animator);

// 动态混合多个动画
var mixer = AnimationLayerMixerPlayable.Create(graph, 2);
var clip1 = AnimationClipPlayable.Create(graph, idleClip);
var clip2 = AnimationClipPlayable.Create(graph, runClip);
graph.Connect(clip1, 0, mixer, 0);
graph.Connect(clip2, 0, mixer, 1);
output.SetSourcePlayable(mixer);

graph.Play();
// 通过 mixer.SetInputWeight 控制混合权重
```

### Animator 更新模式
- **Normal**：Update 中更新（受 Time.timeScale 影响）
- **Animate Physics**：FixedUpdate 中更新（物理相关动画）
- **Unscaled Time**：不受 Time.timeScale 影响（UI 动画）

## 面试官常见追问
- Animator 的 `Has Exit Time` 是什么？（勾选时，Transition 必须等当前动画播放到一定比例才能切换；不勾选则参数满足立即切换）
- `Any State` 是什么？（特殊的源状态，从任何状态都可以触发转换，适合受伤/死亡等全局响应）
- Root Motion 是什么？（动画驱动角色位移，由动画师控制移动而非代码）
- IK（反向运动学）在 Mecanim 中怎么用？（设置 Layer 的 IK Pass，在 `OnAnimatorIK()` 回调中设置 IK 目标）

## 我曾经的误区 / 网上常见错答
- **错**："Blend Tree 只是动画之间的过渡" —— Blend Tree 是参数驱动的连续混合，不是离散的状态过渡
- **错**："PlayableGraph 替代了 Animator" —— PlayableGraph 是底层 API，给 Animator 提供更灵活的播放控制，不是替代
- **错**："AnimatiorController 中的 Layer 只是分组" —— Layer 真正的作用是叠加动画（上半身射击 + 下半身移动），配合 Avatar Mask
