## 🎯 一句话结论（自测用）
> CPU Cache 利用局部性原理加速内存访问——时间局部性（刚访问的数据很可能再次被访问）和空间局部性（刚访问的数据附近的数据很可能被访问）。Cache Line 是 CPU 缓存的最小单位（通常 64 字节），一次从内存读取一整行。伪共享（False Sharing）是多线程性能杀手——两个线程修改同一 Cache Line 的不同变量，导致 Cache Line 在两颗核心间反复 ping-pong。

## ✅ 标准答案（结构化、可背诵，2分钟内讲完）
1. **CPU Cache 层级**：L1（最快最小 32KB） -> L2（中等 256KB） -> L3（慢但大 数MB） -> 主存
2. **局部性原理**：
   - **时间局部性**：刚访问过的数据短期内可能再次被访问（如循环中的计数器）
   - **空间局部性**：刚访问的数据的相邻数据可能随后被访问（如数组遍历）
   - CPU Cache 通过缓存近期访问的数据和相邻数据来利用这两种局部性
3. **Cache Line**：
   - 主存与 Cache 之间传输的最小单位（通常 64 字节）
   - 即使只读 1 个字节，也会拉取整个 64 字节的 Cache Line
   - 有利于空间局部性——连续访问的数据已在缓存中
4. **伪共享（False Sharing）**（网易引擎面高频）：
   - 两个线程各自修改同一个 Cache Line 中的不同变量
   - 虽然两者不共享同一变量，但 Cache 一致性协议（MESI）会强制 Cache Line 在两颗核心间同步
   - 导致大量无效的 Cache Line 迁移和总线流量——性能严重下降
   - 解决方法：变量填充对齐到 Cache Line 边界（C++ 使用 `alignas(64)`）

## 🔍 详细解析

**MESI 协议**：Cache 一致性协议，每行有四种状态：
- **Modified**：只有当前缓存有，且被修改过（需写回内存）
- **Exclusive**：只有当前缓存有，且与内存一致（可安全丢弃）
- **Shared**：多个缓存都有，与内存一致
- **Invalid**：无效，不能使用

**伪共享示例**（C++）：
```cpp
struct Data { int a; int b; }; // a 和 b 在同一 Cache Line (64B)
// Thread 1: data.a++;
// Thread 2: data.b++;
// -> 虽然修改不同变量，但同一 Cache Line 导致 ping-pong
// 解决：alignas(64) int a; alignas(64) int b;
```

**如何利用 Cache 友好性优化代码**：
- 遍历二维数组按行优先（C 语言行主序）
- 使用 `vector` 而非 `list`（连续内存 = 高缓存命中率）
- 结构体字段按访问频率排列（热字段聚集在一起）

## 💬 面试官常见追问
- "数组遍历时行优先和列优先哪个快？为什么？" -> C/C++ 行优先更快——连续访问内存，Cache Line 命中率高。列优先会导致每次访问都在不同的 Cache Line 上，大量 Cache Miss
- "如何检测伪共享？" -> 通过 perf/Intel VTune 查看 Cache Miss 率；或通过压测对比填充前后的性能

## ⚠️ 我曾经的误区 / 网上常见错答
- 误区：Cache 越大性能越好。L1 缓存大了会降低速度（访问延迟增加），各级缓存大小是精心权衡的结果
- 误区：只有共享变量才需要同步。伪共享下即使变量不相关，只要在同一 Cache Line 就可能导致性能问题
