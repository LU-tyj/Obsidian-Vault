## 🎯 一句话结论（自测用）
> 进程是资源分配的基本单位（独立地址空间），线程是 CPU 调度的基本单位（共享进程地址空间）。多线程共享堆和全局变量、独立拥有栈和寄存器。协程是在用户态由程序自己调度的轻量"线程"（如 Unity 协程、Lua 协程），运行在单个线程内。

## ✅ 标准答案（结构化、可背诵，2分钟内讲完）
1. **进程**：
   - 操作系统资源分配的基本单位
   - 拥有独立的地址空间（代码段、数据段、堆、栈）
   - 进程间通信需要 IPC（管道、共享内存、消息队列、Socket 等）
   - 创建和切换开销大（需要切换页表、刷新 TLB）

2. **线程**：
   - CPU 调度的基本单位
   - 同一进程内的线程共享地址空间（堆、全局变量、文件描述符）
   - 每个线程拥有独立的栈、寄存器、PC（程序计数器）
   - 切换开销比进程小（不需要切换地址空间）

3. **协程**：
   - 用户态的"轻量级线程"，由程序（而非 OS）调度
   - 运行在单线程内，切换几乎零开销（只切换栈/寄存器）
   - Unity 协程：基于 Csharp IEnumerator + yield，主线程运行
   - 不是真正的多线程——不能利用多核，不适合密集计算

4. **多线程 vs 多进程选型**：
   - 多线程：适合 IO 密集型（数据共享方便，但需处理同步）
   - 多进程：适合 CPU 密集型（各自独立，崩溃不互相影响，但通信开销大）

## 🔍 详细解析

**共享内存区域**（网易互娱高频）：
- 堆：线程共享
- 全局/静态变量：线程共享
- 栈：线程独立
- 寄存器、PC：线程独立
- 文件描述符表：线程共享

**进程间通信方式**：
| 方式 | 特点 |
|------|------|
| 管道(Pipe) | 半双工，父子进程间 |
| 命名管道(FIFO) | 无关进程间 |
| 共享内存 | 最快，需配合信号量 |
| 消息队列 | 消息的链表 |
| Socket | 跨网络 |
| 信号(Signal) | 异步通知 |

## 💬 面试官常见追问
- "多线程共享哪些内存区域？哪些不共享？" -> 堆和全局变量共享，栈和寄存器不共享
- "协程和线程的根本区别？" -> 线程由 OS 抢占式调度，协程由程序协作式调度。协程切换不需要陷入内核态
- "为什么进程切换比线程切换慢？" -> 进程切换需要切换页表、刷新 TLB Cache，线程切换只切换寄存器和栈指针

## ⚠️ 我曾经的误区 / 网上常见错答
- 误区：Unity 协程是多线程。Unity 协程运行在主线程，不能在协程里做密集计算（会卡主线程）
- 误区：协程比线程快所以应该多用协程。协程不能利用多核，对于计算密集型任务应该用线程或 Job System
