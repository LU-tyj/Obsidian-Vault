## 1 Introduction
游戏循环是游戏的核心，处理每一个输入输出，调用update函数，在关闭游戏前不断地运行。
但也带来了几个问题：
1. 不同设备的循环更新时间应该相同
2. update 与 render 不能产生冲突矛盾
3. 每个物理循环的时间都是固定了（为了遵循物理规律）

---

## 2 Implement
为了解决这些问题，我们需要思考下面的内容：
- 我们需要处理两个时间 $t_{real}$ 和 $t_{physics}$ ，要使得现实时间和物理循环时间要有联系
- GameLoop可以update多次来保证时间同步，最后再用render来弥补剩余时间
	![[GameLoop.png]]
- 要处理如果update帧率为60而显示的帧率为70，这样除不尽的问题（即半个update循环渲染要怎么渲的问题）

我们看下面这段代码，可以满足上面提到的要求
```cpp
double t = 0.0;
double dt = 0.01; // 物理更新时间

double currentTime = hires_time_in_seconds();  // 现实时间
double accumulator = 0.0;

State previous;  
State current; 
 
while (!quit)
{
	double newTime = time();
	double frameTime = newTime - currentTime; // 渲染帧率
	if (frameTime > 0.25) frameTime = 0.25;
	currentTime = newTime;
	accumulator += frameTime;
	
	// 物理循环
	while (accumulator >= dt)
	{
		previousState = currentState;
		integrate(currentState, t, dt);
		t += dt;
		accumulator -= dt;
	}
	
	// 对状态进行插值
	const double alpha = accumulator / dt;
	State state = currentState * alpha + previousState * (1.0 - alpha);
	
	// 渲染插值预测的状态
	render(state);
}
```
