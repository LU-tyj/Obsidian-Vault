## 一句话结论（自测用）
> 模板 = 编译期"类型参数化"，类似蓝图生成代码。函数模板 + 类模板实现泛型编程。特化（偏特化）为特定类型提供定制实现。模板定义必须放在头文件（编译期实例化需要完整定义）。游戏中使用模板实现通用对象池、事件分发器等。

## 标准答案（结构化、可背诵，2分钟内讲完）
1. **函数模板与类模板**：将类型作为参数，编译器在调用时根据实际类型生成对应代码（实例化）。是编译期多态的一种形式。
2. **模板特化（Specialization）**：为特定类型提供不同的实现。全特化：所有模板参数都确定；偏特化：部分参数确定或对参数加约束（如指针类型）。
3. **非类型模板参数**：模板参数不一定是类型，可以是整数、枚举等编译期常量。如 `std::array<int, 10>` 的 10。
4. **模板编译分离问题**：模板定义不能简单地放 .cpp 中。因为模板在调用处按需实例化，编译器需要看到完整定义。解法：全部放头文件（推荐），或用显式实例化 `template class MyClass<int>;`。
5. **SFINAE**：Substitution Failure Is Not An Error。模板参数替换失败时不报错，而是从候选集中移除，让编译器尝试其他重载。是现代 C++ 元编程的基础（`std::enable_if`）。

## 详细解析

### 编译期多态与运行期多态的对比
| | 模板（编译期） | 虚函数（运行期） |
|---|---|---|
| 时机 | 编译期确定 | 运行期查虚表 |
| 性能 | 无运行时开销 | 有虚表查表开销 |
| 代码体积 | 每类型生成一份（代码膨胀） | 一份代码 |
| 灵活性 | 编译后不可变 | 运行时可动态替换 |
| 典型场景 | STL 容器、算法 | 角色/实体多态 |

### 模板特化示例
```cpp
// 通用模板
template<typename T>
class ObjectPool {
    T* Allocate() { return new T(); }
};
// 指针类型偏特化
template<typename T>
class ObjectPool<T*> {
    T* Allocate() { return new T(); } // 不同实现
};
```

### 变参模板（C++11）
```cpp
template<typename... Args>
void Log(Args... args) {
    // 递归展开参数包
}
```
用于实现类型安全的 printf、tuple 等。

## 面试官常见追问
- 模板代码膨胀怎么解决？（提取与非类型参数无关的代码到非模板基类；如 `std::vector<T*>` 可共享大部分实现）
- typename 和 class 关键字在模板中有什么区别？（声明模板参数时完全等价；typename 还用于标识"依赖类型"——`typename T::value_type`）
- 什么是 CRTP？（奇异递归模板模式：`class Derived : public Base<Derived>`，用编译期多态替代运行时虚函数，无虚表开销）
- 模板元编程了解吗？（利用模板在编译期做计算，如图灵完备的编译期计算）

## 我曾经的误区 / 网上常见错答
- **错**："模板只是简单的文本替换" —— 模板有类型检查、重载决议、SFINAE 等复杂机制，远非宏可比
- **错**："模板类中所有方法都会被实例化" —— 只有被调用的成员函数才会实例化
- **错**："模板特化和函数重载是一回事" —— 特化是模板机制、参与模板参数推导；函数重载是另一套独立的决议机制
