_Define behavior in a subclass using a set of operations provided by its base class._

## 1 Motivation
当我们写一个类，要有很多继承的子类时，就比如 `superpower`，然后提供各种各样的能力以及释放能力的特效时，如果使用多次继承，会产生很多代码冗余重复，以及耦合，导致`superpower`的代码渗透到引擎的各个方面，难以修改。因此可以使用 **Sandbox**。
>一般来说，当你有很多子类的时候，可以考虑数据驱动的方法，比如[[4.1 Bytecode]]里提及的；但是如果子类的效果逻辑复杂（一堆if else switch case），使用Bytecode中执行会非常复杂，要写很多指令，因此可以使用 Sandbox。

沙盒模式是：==一个基类定义了一个抽象的沙盒方法和一些预定义的操作集合。通过将它们设置为受保护的状态以确保它们仅供子类使用。每个派生出的沙盒子类根据父类提供的操作来实现沙盒函数。==

是一个简单的模式，但能解决很多问题。它使所有的耦合都集中在基类，绝大部分操作在子类，更容易维护。

## 2 Sample
写一个Superpower基类，给它添加一个Skylaunch的子类（超级弹跳）
这个基类耦合了很多的代码，比如：角色的位置、音效等。而 `activate` 就是我们的沙盒函数，子类通过调用其实现的方法来重写这个函数。

```cpp
class Superpower
{
protected:
  virtual void activate() = 0;

  void move(double x, double y, double z)
  {
    // Code here...
  }

  void playSound(SoundId sound, double volume)
  {
    // Code here...
  }

  void spawnParticles(ParticleType type, int count)
  {
    // Code here...
  }
  double getHeroX()
  {
    // Code here...
  }

  double getHeroY()
  {
    // Code here...
  }

  double getHeroZ()
  {
    // Code here...
  }

  // Existing stuff...
};
```

这就是我们子类的实现，利用Superpower中的函数重写了`activate`
```cpp
class SkyLaunch : public Superpower
{
protected:
  virtual void activate()
  {
    if (getHeroZ() == 0)
    {
      // On the ground, so spring into the air.
      playSound(SOUND_SPROING, 1.0f);
      spawnParticles(PARTICLE_DUST, 10);
      move(0, 0, 20);
    }
    else if (getHeroZ() < 10.0f)
    {
      // Near the ground, so do a double jump.
      playSound(SOUND_SWOOP, 1.0f);
      move(0, 0, getHeroZ() + 20);
    }
    else
    {
      // Way up in the air, so do a dive attack.
      playSound(SOUND_DIVE, 0.7f);
      spawnParticles(PARTICLE_SPARKLES, 1);
      move(0, 0, -getHeroZ());
    }
  }
};
```
>像这样条件复杂的能力就难以使用数据驱动

## 3 Design Decision
我们已经了解了沙盒模式，现在来思考一下使用时的决策。很自然的能想到一些问题，比如：要把一堆函数都塞在基类吗？基类如何获取状态（比如音频播放系统）？

### 3.1 基类中需要提供什么操作
这里就有两个极端，要么基类只有一个activate函数，要么就是基类包含子类需要的所有功能。从前者转变到后者的过程中，子类耦合越来越少，而基类与其他类的耦合越来越大，越来越难维护。

为了解决这个问题，可以使用这些方法：
- 如果一个方法只被少量的子类使用，那么就在这些子类中实现。
- 如果提供的操作，其实现仅仅是对一些外部系统调用的二次封装，那么它并没有带来多少价值。在这种情况下，直接调用外部系统更为简单。（但也可以为了不暴露接口给子类，进行包装）

### 3.2 要把一堆函数都塞在基类吗？
可以创造一个辅助类来帮助简化基类代码，进行维护。比如把所有和音乐播放相关的函数都放入 `SoundPlayer` 辅助类中。
```cpp
class SoundPlayer
{
  void playSound(SoundId sound, double volume)
  {
    // Code here...
  }

  void stopSound(SoundId sound)
  {
    // Code here...
  }

  void setVolume(SoundId sound)
  {
    // Code here...
  }
};
```

这样就可以通过下面的操作进行调用。
```cpp
class Superpower
{
protected:
  SoundPlayer& getSoundPlayer()
  {
    return soundPlayer_;
  }

  // Sandbox method and other operations...

private:  
  SoundPlayer soundPlayer_;
};
```

### 3.3 基类如何获得外部状态
- 最简单的方法就是传进来当一个属性进行存储（利用构造函数）

- 进行分段初始化，即用构造函数创建一个空的对象，再在子类中调用 `init` 方法进行赋值。但这个方法需要每次都使用 `init`，忘记了就会变成空对象。也可以直接把整个创建和赋值的过程封装到同一个函数中：
```cpp
Superpower* createSkyLaunch(ParticleSystem* particles)
{
  Superpower* power = new SkyLaunch();
  power->init(particles);
  return power;
}
```

- 将状态静态化，这样只需要在早些时候进行初始化，那么所有的子类示例都可以获得这个系统。
```cpp
class Superpower
{
public:
  static void init(ParticleSystem* particles)
  {
    particles_ = particles;
  }

  // Sandbox method and other operations...

private:
  static ParticleSystem* particles_;
};
```

- 使用服务定位器。前面的方法都是需要之前就加载进去了，而另一个方法就是让基类把它需要的状态拉进去处理。
```cpp
class Superpower
{
protected:
  void spawnParticles(ParticleType type, int count)
  {
    ParticleSystem& particles = Locator::getParticles();
    particles.spawn(type, count);
  }

  // Sandbox method and other operations...
};
```
