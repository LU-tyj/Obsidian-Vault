## 二、复习间隔逻辑（艾宾浩斯压缩版）

### 经典艾宾浩斯间隔

| 轮次 | 间隔 | 目的 |
|------|------|------|
| R1 | 当天 | 首次学习，理解概念 |
| R2 | 1 天后 | 快速回顾，合上笔记自测 |
| R3 | 3 天后 | 不看笔记口述标准答案 |
| R4 | 7 天后 | 计时回答 + 处理追问 |
| R5 | 15 天后 | 模拟面试问答 |
| R6 | 30 天后 | 冲刺阶段全面回顾 |

### 为何需要压缩

- **经典方案**每篇笔记需要 6 次接触，总耗时 ≈ 77 小时（136 × 34min），平均每天 1.3h，超出每日 1h 的硬约束
- **59 天窗口**无法容纳 30 天间隔的完整展开（第一批笔记的 R6 要等到 8 月初，最后一批要到 9 月底）
- **实际瓶颈**不在复习次数，而在首次学习阶段（需要理解 + 整理 + 记忆，每篇 12-15min）

### 压缩策略：三轮递进

将 6 次艾宾浩斯复习合并为 **3 轮递进式复习**，时间分配向首轮倾斜：

| 轮次 | 覆盖 | 每篇耗时 | 对应艾宾浩斯 | 总耗时 |
|------|------|----------|-------------|--------|
| **第一轮**（首次学习） | 154 篇 | 12-15 min | R1 + R2（学完次日快速回顾） | ~30 h |
| **第二轮**（间隔复習） | 154 篇 | 5-7 min | R3 + R4（闭卷自测 + 口述） | ~14 h |
| **第三轮**（冲刺查漏） | ~80 篇重点 + 56 篇快扫 | 5 min（重点）/ 2 min（快扫） | R5 + R6（模拟问答 + 全面回顾） | ~9 h |

- **总耗时**：~53 小时 / 59 天 ≈ **0.9 小时/天**，在 1 小时约束内
- **牺牲**：30 天间隔的独立复习 → 被合并到第三轮的快扫中。对于已掌握的内容影响极小（30 天后遗忘率本就不高），薄弱内容会在第三轮被重点照顾
- **保留**：1 天和 3-7 天的关键间隔 → 通过在每天学习新课前花 5-10 分钟快速回顾昨日/前三日内容来覆盖

### 每日时间模板

```
┌─────────────────────────────────────────┐
│ 前日回顾（5 min）                         │
│ 合上笔记，默写/口述昨天学的 4 篇的核心结论   │
├─────────────────────────────────────────┤
│ 新课学习（45-50 min）                     │
│ 每篇 12 min：读 → 理解 → 背标准答案        │
├─────────────────────────────────────────┤
│ 三日回顾（5 min，每周 2-3 次）              │
│ 快速过 3 天前的笔记，标记遗忘的             │
└─────────────────────────────────────────┘
```

## 五、手动复习方法

核心工具有两个：**复习追踪表**（唯一真源）+ `/update-review` 技能（自动化脚本）。你只需要手动维护追踪表，其余由脚本自动完成。

### 5.1 追踪体系

| 层级 | 工具 | 记录什么 | 谁维护 |
|------|------|----------|--------|
| 全局 | [[复习追踪表]] | 所有笔记的状态、频率、复习次数、日期 | **你手动改** |
| 单篇 | 笔记 frontmatter | `status` / `last_reviewed` / `next_review` | **脚本自动同步** |

每篇笔记 frontmatter 中会被脚本自动更新的字段：

```yaml
status: new          # new → reviewing → mastered
last_reviewed:       # 上次复习日期，如 2026-07-04
next_review:         # 下次复习日期（脚本按间隔自动计算）
```

### 5.2 `/update-review` 技能用法

在 Claude Code 中输入 `/update-review`（或说"同步复习进度""今天该复习哪些笔记"），脚本会自动完成：

1. **同步 frontmatter**：以追踪表为准，把 `status` / `last_reviewed` / `next_review` 写回每篇笔记
2. **计算下次复习日期**：按艾宾浩斯间隔（1→1d, 2→3d, 3→7d, 4→15d, 5+→30d）自动填充 `next_review` 列
3. **更新统计面板**：重新生成各专题的 new / reviewing / mastered 计数和完成率
4. **生成今日待复习清单**：列出 `next_review` 已到期且未掌握的笔记，按频率降序排列

> **你唯一需要做的**：复习完一篇笔记后，在追踪表中更新对应的 `状态`、`上次复习`、`复习次数`。然后跑一次 `/update-review`，其余全部自动处理。

### 5.3 每日操作流程

**学新课（第一轮）**：
1. 打开笔记，读一遍 → 合上笔记自述标准答案 → 对照原文看漏了什么
2. 到 [[复习追踪表]] 把对应行的 `状态` 改为 `reviewing`，`首次学习` 填今天日期
3. 运行 `/update-review` → 脚本自动同步 frontmatter + 计算下次复习日期

**复习旧课（第二、三轮）**：
1. 运行 `/update-review` → 查看输出的"今日待复习清单"
2. 按清单顺序复习，合上笔记口述标准答案：
   - 能脱稿讲清 → 追踪表中 `状态` 改为 `mastered`，复习次数 +1
   - 卡顿但能回忆关键点 → `状态` 保持 `reviewing`，`上次复习` 更新为今天，复习次数 +1
   - 完全忘了 → 重新读一遍，`状态` 保持 `reviewing`
3. 再次运行 `/update-review` → 脚本同步所有变更

### 5.4 复习间隔参考

| 第 N 次复习 | 1 | 2 | 3 | 4 | 5+ |
|-------------|---|---|---|---|----|
| 距上次间隔 | 1 天 | 3 天 | 7 天 | 15 天 | 30 天 |

> 不需要手动计算间隔——脚本会自动算好 `next_review`。每天跑一次 `/update-review`，按输出的待复习清单挑 5-10 篇过一遍即可。频率 1 的低频题过一轮就够，频率 3 的高频题多轮重复直到脱稿。

### 5.5 各轮次侧重点

1. **第一轮（首次学习）**：重在理解 + 背诵标准答案。学完一篇就在追踪表标记 `reviewing`，跑 `/update-review` 同步。
2. **第二轮（间隔复习）**：重在合上笔记自测。每天跑 `/update-review` 获取待复习清单，按清单逐篇过。`status: reviewing` 保持直到能脱稿。
3. **第三轮（冲刺）**：只过 `reviewing` 和频率 3 的高频题。`mastered` 的快速扫一眼即可，每篇不超过 2 分钟。
