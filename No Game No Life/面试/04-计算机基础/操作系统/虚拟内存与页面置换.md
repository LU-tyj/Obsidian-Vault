## 🎯 一句话结论（自测用）
> 虚拟内存让每个进程拥有独立的虚拟地址空间（32位=4GB，64位=超大），通过 MMU + 页表映射到物理内存。页面置换算法是在物理内存不足时决定换出哪些页面的策略，常见有 FIFO、LRU、Clock（近似 LRU）。

## ✅ 标准答案（结构化、可背诵，2分钟内讲完）
1. **虚拟内存的核心作用**：
   - 每个进程拥有独立的虚拟地址空间，进程间隔离
   - 程序不必全部加载到物理内存（需求分页/按需调页）
   - 物理内存作为磁盘的缓存，通过缺页中断按需加载

2. **虚拟地址到物理地址的转换**：
   - 通过 MMU（内存管理单元）+ 多级页表完成
   - 虚拟地址 = 页号 + 页内偏移
   - 页表存储页号到物理帧号的映射，TLB 缓存热门映射加速

3. **常见页面置换算法**（网易雷火高频）：

| 算法 | 策略 | 优点 | 缺点 |
|------|------|------|------|
| **FIFO** | 淘汰最先进入的页面 | 简单 | Belady 异常（增加页面反而缺页增多） |
| **LRU** | 淘汰最久未使用的页面 | 接近最优 | 实现成本高（需记录访问时间） |
| **Clock / NRU** | 环形链表 + 访问位，淘汰访问位=0 的页 | 近似 LRU，开销小 | 不严格 LRU |
| **OPT** | 淘汰未来最长时间不用的页面 | 理论最优 | 不可能实现（需预知未来） |

4. **缺页中断流程**：访问页面未在物理内存 -> 触发缺页异常 -> OS 从磁盘读取页面到物理内存 -> 更新页表 -> 重试访问

## 🔍 详细解析

**多级页表**：
- 单级页表太大（32位系统需要 4MB 页表）
- 多级页表只在需要时分配中间级别的页表，节省内存
- x86_64 使用 4 级页表

**TLB（Translation Lookaside Buffer）**：
- CPU 内部的地址翻译缓存
- 进程切换需要刷新 TLB（或打上 ASID 标签区分进程）
- TLB miss 需要走页表查询，开销大

**页表项（PTE）的标志位**：Present（是否在内存）、Dirty（是否被修改过）、Accessed（是否被访问过）、Read/Write、User/Supervisor

## 💬 面试官常见追问
- "物理内存不够时怎么处理？" -> 页面置换（swap out）不活跃的页面到磁盘交换区；或 OOM Killer 杀掉进程
- "TLB 命中率怎么提高？" -> 增大 TLB 大小、使用大页（Huge Pages）、合理设计数据结构利用空间局部性

## ⚠️ 我曾经的误区 / 网上常见错答
- 误区：虚拟内存 = 磁盘交换。虚拟内存是地址空间抽象，磁盘交换只是其中一部分
- 误区：物理内存够大就不需要虚拟内存。虚拟内存还提供进程隔离、安全保护等功能，即使物理内存足够仍然需要
