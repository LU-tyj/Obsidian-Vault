## 1 Motivation
当我们点击一个ui或者种种事情时，操作系统都会发送一个事件，然后让程序处理。所以一定会有一个死循环来不断的用 `getNextEvent()` 来接收数据，但应用程序会在需要时才引入事件，所以平时就要把这些事件都存储起来，当调用上面的函数时，会把最早的事件取出并交给应用程序。

但这样就会有一些问题：就比如说在游戏中使用音乐系统，我们通过playersound来加载音效，找到播放源，然后播放。
- 当音效引擎完全处理完播放请求前，API的调用会一直阻塞着调用者，如果要在磁盘中加载音乐文件，那么游戏就卡住了。而且如果两个敌人受伤音效一起播放，会变得很响，如果一堆敌人一起受伤，声音可能因为超过临界值而中断了。
- 代码库中很多不同的系统会涉及音效的调用，而这些又分配在不同线程上，但明显没有线程同步，所以会产生一个吃闲饭的音频线程（任务都给其他线程了）
- 请求在错误的线程中执行。

事件队列模式：“事件队列是一个按照先进先出顺序存储一系列通知或请求的队列。发出通知时系统会将该请求置入队列并随即返回，请求处理器随后从事件队列中获取并处理这些请求。请求可由处理器直接处理或转交给对其感兴趣的模块。这一模式对消息的发送者与受理者进行了解耦，使消息的处理变得动态且非实时。”

---

## 2 When and how to use it
如果只是对消息的发送者和传输者进行解耦，那么[[2.3 Observer Pattern]]&[[2.1 Command Pattern]]就可以解决问题而且复杂度还低。需要对时间进行解耦时，一个队列就好了
>一般一个数组就好了，不用想复杂的数据结构

要注意：
- 中心事件队列是一个全局变量
- 游戏世界的状态任你掌控
- 你可能会进入一个死循环（A->B, B->A,A->B,...)

---

## 3 Sample
我们直接看用环形数组作为事件队列，处理声音系统的例子。
我们想实现的目的：时间上的解耦，能提前加载声音，能处理声音重复的问题

1. 一个结构体，方便存放数据
```cpp
struct PlayMessage
{
	SoundId id;
	int volume;
}
```

2. 有一个环形列表，可以节省空间
```cpp
class Audio
{
public:
  static void init()
  {
    head_ = 0;
    tail_ = 0;
  }

  // Methods...
private:
  static int head_;
  static int tail_;

  // Array
  static const int MAX_PENDING = 16;

  static PlayMessage pending_[MAX_PENDING];
  static int numPending_;
};
```

3. update方法（执行列表中的事件），`head_ = (head_++) % MAX_PENDING` 可以使数据绕回来
```cpp
void Audio::update()
{
  // If there are no pending requests, do nothing.
  if (head_ == tail_) return;

  ResourceId resource = loadSound(pending_[head_].id);
  int channel = findOpenChannel();
  if (channel == -1) return;
  startSound(resource, channel, pending_[head_].volume);

  head_ = (head_ + 1) % MAX_PENDING;
}
```

4. 这里有两个作用
- 在 `tail_` 指针处存储数据
- 遍历列表，合并相同的音效，防止出现重合音量高的问题（要考虑开销）
```cpp
void Audio::playSound(SoundId id, int volume)
{
  // Walk the pending requests.
  for (int i = head_; i != tail_;
       i = (i + 1) % MAX_PENDING)
  {
    if (pending_[i].id == id)
    {
      // Use the larger of the two volumes.
      pending_[i].volume = max(volume, pending_[i].volume);

      // Don't need to enqueue.
      return;
    }
  }

  assert((tail_ + 1) % MAX_PENDING != head_);

  // Add to the end of the list.
  pending_[tail_].id = id;
  pending_[tail_].volume = volume;
  tail_ = (tail_ + 1) % MAX_PENDING;
}
```

这样无论什么线程调用 `playsound` 函数，都只是一个存储信息而已，也没有什么加载，`update` 交给音频线程解决。
