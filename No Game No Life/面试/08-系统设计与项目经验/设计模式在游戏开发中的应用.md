## 🎯 一句话结论（自测用）
> 游戏开发中最常用的设计模式：单例（GameManager/AudioManager）、观察者（事件系统/UI更新）、对象池（子弹/特效复用）、状态模式/FSM（角色状态管理）、工厂（敌人/道具生成）、组件模式（Unity 核心架构）、命令模式（操作回放/撤销）。SOLID 七原则中面试最常问开闭原则和依赖倒置。

## ✅ 标准答案（结构化、可背诵，2分钟内讲完）
1. **单例模式**：全局唯一实例（GameManager、AudioManager、ResourceManager）。Unity 中通过 Awake + static Instance + DontDestroyOnLoad 实现。注意多线程安全（Csharp 用 Lazy<T> 或静态构造）。
2. **观察者模式**：一对多依赖关系，主题变化时自动通知观察者。Csharp 实现：event/delegate、UnityEvent。核心注意点：场景切换时注销事件，否则导致内存泄漏。
3. **对象池模式**：复用频繁创建/销毁的对象，减少 GC。维护 inactive 对象队列，预热 + 动态扩容 + 状态重置。
4. **状态模式/FSM**：角色行为随状态变化（待机、巡逻、攻击、死亡）。实现方式：enum+switch（简单）、状态类+IState 接口（可扩展）、Animator 状态机（动画）。
5. **工厂模式**：对象创建与使用分离。简单工厂一个类根据参数创建不同产品；工厂方法由子类决定创建什么。
6. **组件模式**：Unity 本身的核心架构，将功能分散到独立 Component，组合优于继承。
7. **命令模式**：封装请求为对象。应用：RTS 单位命令队列、回放系统、撤销/重做。

## 🔍 详细解析

### Unity 单例安全实现
```csharp
public class GameManager : MonoBehaviour
{
    public static GameManager Instance { get; private set; }
    void Awake()
    {
        if (Instance != null && Instance != this)
        {
            Destroy(gameObject);
            return;
        }
        Instance = this;
        DontDestroyOnLoad(gameObject);
    }
}
```

### 事件中心实现
```csharp
public class EventManager
{
    private static Dictionary<string, Action<object>> events = new();
    
    public static void Register(string eventType, Action<object> handler)
        => events[eventType] += handler;
    
    public static void UnRegister(string eventType, Action<object> handler)
        => events[eventType] -= handler;
    
    public static void Trigger(string eventType, object data)
        => events[eventType]?.Invoke(data);
}
```

### SOLID 七原则速查
| 原则 | 核心 |
|------|------|
| SRP 单一职责 | 一个类只做一件事 |
| OCP 开闭原则 | 对扩展开放，对修改关闭 |
| LSP 里氏替换 | 子类可替换父类 |
| ISP 接口隔离 | 多个专用接口 > 一个大接口 |
| DIP 依赖倒置 | 依赖抽象不依赖具体 |
| 迪米特法则 | 最少知道原则 |
| 合成复用 | 组合优于继承 |

## 💬 面试官常见追问
- **单例的缺点？** → 全局状态（测试困难）、隐式依赖（可读性差）、违反单一职责、生命周期不明确（DontDestroyOnLoad 一直占用内存）
- **UnityEvent vs Csharp event？** → UnityEvent 可在 Inspector 可视化配置但性能较低（反射开销）；Csharp event 性能高但不可序列化
- **命令模式和策略模式的区别？** → 命令模式封装请求为对象（可撤销/队列化）；策略模式封装算法族（可运行时替换）

## ⚠️ 我曾经的误区 / 网上常见错答
- 误区：设计模式越多代码越好。过度使用增加复杂度，应遵循"够用就好"原则
- 误区：Unity 单例不需要考虑线程安全。Unity 主线程模式下大多数不需要，但如果结合 Task.Run 则需要注意
