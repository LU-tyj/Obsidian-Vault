## 🎯 一句话结论（自测用）
> 简单工厂：一个工厂根据参数创建不同产品。工厂方法：子类决定具体实例化哪个类。抽象工厂：创建一系列相关产品族。游戏用工厂创建敌人/道具/技能。

## ✅ 标准答案（结构化、可背诵，2分钟内讲完）
1. **简单工厂（Simple Factory）**：一个工厂类，根据传入参数创建不同类型对象。违反开闭原则（新增类型需改工厂）
2. **工厂方法（Factory Method）**：基类定义创建对象的接口，子类决定创建哪个具体类。符合开闭原则
3. **抽象工厂（Abstract Factory）**：创建一系列相关或依赖的对象族（如 UI 工厂 -> Button + TextField），无需指定具体类
4. **游戏应用**：敌人工厂（根据等级/类型创建不同敌人）、道具工厂、技能工厂

## 🔍 详细解析

### 简单工厂
```csharp
public class EnemyFactory
{
    public static Enemy CreateEnemy(string type)
    {
        switch (type)
        {
            case "Orc": return new Orc();
            case "Elf": return new Elf();
            default: throw new ArgumentException();
        }
    }
}
```
缺点：新增类型需修改 switch，违反开闭原则。

### 工厂方法
```csharp
public abstract class EnemyFactory
{
    public abstract Enemy CreateEnemy();
}

public class OrcFactory : EnemyFactory
{
    public override Enemy CreateEnemy() => new Orc();
}

public class ElfFactory : EnemyFactory
{
    public override Enemy CreateEnemy() => new Elf();
}
```
优点：新增类型只需新增子类，符合开闭原则。

### 抽象工厂
```csharp
public interface IGUIFactory
{
    Button CreateButton();
    TextField CreateTextField();
}

public class DarkThemeFactory : IGUIFactory
{
    public Button CreateButton() => new DarkButton();
    public TextField CreateTextField() => new DarkTextField();
}
```
适用场景：需要一组相关对象协同工作（如 UI 主题切换）。

### 三种工厂对比
| | 简单工厂 | 工厂方法 | 抽象工厂 |
|--|---------|---------|---------|
| 创建目标 | 单一产品 | 单一产品 | 产品族 |
| 扩展方式 | 改工厂类 | 加子类 | 加子工厂 |
| 复杂度 | 低 | 中 | 高 |
| 开闭原则 | 违反 | 符合 | 符合 |

## 💬 面试官常见追问
- "简单工厂和工厂方法的使用场景？" -> 产品类型少且固定用简单工厂；产品类型经常扩展用工厂方法
- "工厂模式和依赖注入的关系？" -> 工厂负责创建，DI 负责注入。可以结合使用：DI 容器内部用工厂创建对象
- "Unity 中哪里用到了工厂模式？" -> `GameObject.Instantiate` 可以看作工厂；AssetBundle 创建资源也是工厂变体

## ⚠️ 我曾经的误区 / 网上常见错答
- **误区**：简单工厂 = 工厂模式。简单工厂不算 GoF 23 种设计模式，工厂方法和抽象工厂才是
- **误区**：所有对象的创建都要用工厂。简单对象直接 new 即可，过度设计反而降低可读性
