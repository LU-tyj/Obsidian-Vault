## 🎯 一句话结论（自测用）
> 静态链接在编译时将所有依赖库代码复制到可执行文件中（大但可独立运行），动态链接在运行时映射共享库到进程空间（小但依赖 .so/.dll 文件）。可执行文件通过 ELF 的 .dynamic 段或 PE 的导入表知道需要加载哪些动态库。

## ✅ 标准答案（结构化、可背诵，2分钟内讲完）
1. **静态链接**：
   - 编译/链接阶段将所用库函数的目标代码直接复制到可执行文件中
   - 优点：可独立运行（不需要依赖库文件）、加载速度快
   - 缺点：可执行文件体积大、库更新需要重新编译链接、多个进程各自复制浪费内存

2. **动态链接**：
   - 运行时由动态链接器（ld.so / dyld）将共享库映射到进程地址空间
   - 优点：可执行文件小、库更新只需替换 .so/.dll 文件（热更新基础）、多进程共享同一份物理内存
   - 缺点：依赖库文件存在（DLL Hell）、加载时多一步链接

3. **运行时如何知道该加载哪些动态库**：
   - Linux ELF：`.dynamic` 段中记录 `DT_NEEDED` 条目，列出依赖的 .so 文件名
   - Windows PE：导入表（Import Directory）记录依赖的 DLL 和导入函数
   - 动态链接器（`ld.so` / `dyld` / `LdrLoadDll`）根据这些信息在指定路径搜索并加载

## 🔍 详细解析

**链接的大致过程**：
1. 预编译 -> 编译 -> 汇编 -> 目标文件(.o)
2. 链接器将多个 .o 文件和库合并为可执行文件或动态库
3. 链接时做：符号解析（找到每个符号的定义）+ 重定位（修正地址引用）

**动态链接与热更新**：
- 游戏热更新（Unity AssetBundle / Lua 脚本）不涉及 OS 级动态链接
- OS 级动态链接更适合引擎或 C++ Native Plugin 的热更新

**Unity IL2CPP 的链接**：
- IL2CPP 将 Csharp IL 转 C++ 源码再编译为机器码
- iOS 必须用静态链接（AOT），Android 可用动态链接

## 💬 面试官常见追问
- "动态库是怎么被加载到内存的？" -> 操作系统将 .so 映射到进程虚拟地址空间的内存映射段，动态链接器解析符号、做重定位、调用初始化函数
- "静态库和动态库的优缺点分别是什么？" -> 见上方核心回答
- "多个进程加载同一个动态库，内存中会有几份？" -> 物理内存只有一份（操作系统页缓存共享），各进程虚拟地址空间各有一份映射

## ⚠️ 我曾经的误区 / 网上常见错答
- 误区：动态链接的库每次加载都要重新链接。实际上第一次加载后操作系统会缓存，后续进程直接复用
- 误区：静态链接的程序不依赖任何外部库。仍然依赖操作系统的系统调用接口
