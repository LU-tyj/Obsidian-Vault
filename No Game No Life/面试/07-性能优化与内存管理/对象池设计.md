## 🎯 一句话结论（自测用）
> 对象池的核心价值：减少 GC 触发（避免频繁 Instantiate/Destroy）、降低 CPU 峰值（预创建消除运行时分配）、减少内存碎片。关键设计点：预热、动态扩容、回收策略、状态重置。

## ✅ 标准答案（结构化、可背诵，2分钟内讲完）
1. **为什么需要对象池？**
   - 频繁 Instantiate/Destroy 会导致：托管堆分配 + 后续 GC 回收 = 卡顿
   - Instantiate 本身涉及从 Prefab 克隆、Awake/OnEnable 调用，有 CPU 开销
   - 销毁时 Destroy 不会立即释放，而是延迟到帧末
2. **对象池核心设计**：
   - 预热（Pre-warm）：游戏加载时预生成一定数量对象并设置 inactive
   - Get：从池中取出可用对象，激活并返回；如果池空则 Instantiate 新对象
   - Release：回收对象，重置所有状态，设为 inactive 放回池中
   - 动态扩容：池不够时自动生成额外对象
   - 回收策略：可选限制最大数量，超出时真正销毁或延迟回收
3. **Unity 中使用方式**：
   - 维护 inactive GameObject 的 Queue/Stack
   - Unity 2021+ 内置 `UnityEngine.Pool.ObjectPool<T>`
   - 对于非 GameObject 类型（如纯 Csharp 对象），使用泛型 Stack/ObjectPool<T>

## 🔍 详细解析

### 基本实现（GameObject 版）
```csharp
public class GameObjectPool : MonoBehaviour
{
    [SerializeField] private GameObject prefab;
    [SerializeField] private int prewarmCount = 10;
    private Queue<GameObject> pool = new Queue<GameObject>();

    void Start()
    {
        for (int i = 0; i < prewarmCount; i++)
        {
            var obj = Instantiate(prefab);
            obj.SetActive(false);
            pool.Enqueue(obj);
        }
    }

    public GameObject Get()
    {
        var obj = pool.Count > 0 ? pool.Dequeue() : Instantiate(prefab);
        obj.SetActive(true);
        return obj;
    }

    public void Release(GameObject obj)
    {
        obj.SetActive(false);
        pool.Enqueue(obj);
    }
}
```

### Unity 2021+ 内置 ObjectPool
```csharp
private ObjectPool<GameObject> pool;

void Start()
{
    pool = new ObjectPool<GameObject>(
        createFunc: () => Instantiate(prefab),
        actionOnGet: obj => obj.SetActive(true),
        actionOnRelease: obj => obj.SetActive(false),
        actionOnDestroy: obj => Destroy(obj),
        collectionCheck: true,  // 检测重复释放
        defaultCapacity: 10,
        maxSize: 100
    );
}
```

### 关键设计点详解
| 设计点 | 说明 |
|-------|------|
| 预热 | 游戏开始/场景加载时预生成，避免运行时首次 Instantiate 的卡顿 |
| 动态扩容 | 池空时自动生成，避免逻辑中断 |
| 状态重置 | 回收时必须重置 Transform、HP、特效状态等（最容易出 Bug） |
| 最大容量 | 防止无限增长，超出可销毁或延迟回收 |
| 类型安全 | 可对每种 Prefab 创建独立池，或使用 Dict<prefabId, pool> |

## 💬 面试官常见追问
- **状态重置要重置哪些？** → Transform（位置/旋转/缩放）、Rigidbody（速度/角速度）、HP/属性、粒子/音效状态、事件注册
- **什么时候用对象池，什么时候不必要？** → 高频创建销毁（子弹、特效、敌人、UI 列表项）才需要；低频对象（如 BOSS）不需要
- **对象池和 Addressables 怎么配合？** → 用 Addressables 加载 Prefab，实例化后放入对象池管理；Release 时 Addressables.ReleaseInstance
- **池满了怎么办？** → 策略选择：销毁最老的（LRU）、拒绝分配并打印警告、临时扩容

## ⚠️ 我曾经的误区 / 网上常见错答
- 误区：所有对象都用对象池。低频对象池化浪费内存（预生成的对象不一定会用到）
- 误区：回收时 SetActive(false) 就够了。必须重置 Rigidbody 速度、粒子播放状态等，否则下次取出时有残留状态
- 误区：对象池只适用于子弹。UI ScrollView 列表项（列表滚动时复用 Cell）也是典型的对象池场景
