## 一句话结论（自测用）
> 对象池 = 预创建对象并回收复用，替代频繁 `Instantiate`/`Destroy`，核心收益是减少 GC（避免堆分配）和降低 CPU 峰值。关键设计点：预热、动态扩容、回收状态重置、最大数量限制。

## 标准答案（结构化、可背诵，2分钟内讲完）
1. **核心价值**（为什么需要对象池）：
   - **减少 GC**：频繁 `Instantiate` + `Destroy` 产生大量堆分配和 GC 回收
   - **降低 CPU 峰值**：预创建分担了创建开销，运行时几乎无分配
   - **减少内存碎片**：对象复用避免了反复分配释放造成碎片
   - **提升流畅度**：GC 不触发 = 无卡顿
2. **四个关键设计点**：
   - **预热（Pre-warm）**：游戏开始时预生成一定数量，避免运行时创建峰值
   - **动态扩容**：池不够用时自动生成额外对象（设置上限防爆内存）
   - **回收策略**：对象失效时不 Destroy，而是 SetActive(false) 并放回池
   - **状态重置**：回收时必须重置对象所有状态（Transform、生命值、特效等）
3. **通用实现框架**：
   ```csharp
   public class ObjectPool<T> where T : Component {
       Queue<T> pool = new Queue<T>();
       T prefab;
       Transform parent;

       public T Get() {
           T obj = pool.Count > 0 ? pool.Dequeue() : Instantiate(prefab, parent);
           obj.gameObject.SetActive(true);
           return obj;
       }

       public void Return(T obj) {
           obj.gameObject.SetActive(false);
           pool.Enqueue(obj);
       }
   }
   ```

## 详细解析

### 什么时候该用对象池？判断三问
1. 这个对象是否**频繁创建/销毁**？（子弹、粒子、敌人、UI 列表项）
2. 创建 / 销毁是否**有明显性能开销**？（含复杂组件、骨骼动画、碰撞体）
3. 场景中**同时存在的数量**是否可以预估？

### 预热策略
```csharp
// 加载画面时预生成
for (int i = 0; i < prewarmCount; i++) {
    T obj = Instantiate(prefab, poolRoot);
    obj.gameObject.SetActive(false);
    pool.Enqueue(obj);
}
```
预热应放在场景加载阶段，不要阻塞玩家操作。

### 回收时的状态重置（最容易出 Bug 的地方）
必须重置的内容：
- Transform：位置、旋转、缩放
- Rigidbody：速度、角速度
- 脚本内状态：HP、计时器、Buff
- 粒子系统：停止并清除
- Trail Renderer：清除轨迹
- 事件监听：**必须注销**（否则池对象持有过期引用）

推荐实现 `IRecyclable` 接口：`void OnRecycle(); void OnSpawn();`

### 最大容量限制
防止池无限膨胀：设置 `maxSize`，超出时直接 Destroy 而非入池。

## 面试官常见追问
- 对象池满了怎么处理？（拒绝生成 + 报 warning；或替换为更简单的表现；或直接 Destroy 最老的）
- 对象池和 Addressables 怎么配合？（Addressables 负责加载，加载后复制实例进池，释放 AsyncOperationHandle）
- 对象池里的对象能被 GC 吗？（池持有引用，不会被 GC。但如果池是静态变量，永远不释放）
- UniRx / UniTask 有内置的对象池吗？（有，UniRx 的 `MicroCoroutine`、UniTask 的 `UniTaskCompletionSource` 都有内部池化）

## 我曾经的误区 / 网上常见错答
- **错**："对象池就是用一个 List 存着" —— 应该用 Queue/Stack，List 的 Remove 是 O(n)
- **错**："对象池只要 SetActive 就够了" —— 状态重置才是一般对象池代码最常出 bug 的地方
- **错**："对象池越多越好" —— 池本身也占内存（预分配），需要在 GC 收益和内存占用间平衡
- **错**："所有反复创建的对象都要用对象池" —— 如果创建开销极小（如纯 UI 文本），对象池反而增加代码复杂度
