## 🎯 一句话结论（自测用）
> 单例确保全局唯一实例。Unity 中 Awake 判重 + DontDestroyOnLoad。Csharp 用静态构造函数或 Lazy\<T\> 实现线程安全。多线程用双重检查锁定。

## ✅ 标准答案（结构化、可背诵，2分钟内讲完）
1. **定义**：保证一个类只有一个实例，并提供全局访问点
2. **Unity 中单例模板（MonoBehaviour）**：
   - Awake 中判断 `Instance` 是否已存在 -> 存在则 Destroy(gameObject)
   - 使用 `DontDestroyOnLoad(gameObject)` 保证场景切换不销毁
3. **多线程安全（Csharp 纯代码）**：
   - 静态构造函数（CLR 保证只执行一次）
   - `Lazy<T>`（线程安全 + 延迟初始化）
   - 双重检查锁定（double-checked locking）
4. **优缺点**：
   - 优点：统一管理、避免重复创建、全局访问方便
   - 缺点：全局状态测试困难、隐式依赖、违反单一职责原则

## 🔍 详细解析

### Unity MonoBehaviour 单例模板
```csharp
public class GameManager : MonoBehaviour
{
    public static GameManager Instance { get; private set; }

    void Awake()
    {
        if (Instance != null && Instance != this)
        {
            Destroy(gameObject);
            return;
        }
        Instance = this;
        DontDestroyOnLoad(gameObject);
    }
}
```

### Csharp 非 MonoBehaviour 单例（线程安全）
```csharp
// 方案一：静态构造函数（推荐）
public sealed class Singleton
{
    public static Singleton Instance { get; } = new Singleton();
    private Singleton() { }
}

// 方案二：Lazy<T>
public sealed class Singleton
{
    private static readonly Lazy<Singleton> lazy = 
        new Lazy<Singleton>(() => new Singleton());
    public static Singleton Instance => lazy.Value;
    private Singleton() { }
}

// 方案三：双重检查锁定
public sealed class Singleton
{
    private static volatile Singleton _instance;
    private static readonly object _lock = new object();
    
    public static Singleton Instance
    {
        get
        {
            if (_instance == null)
            {
                lock (_lock)
                {
                    if (_instance == null)
                        _instance = new Singleton();
                }
            }
            return _instance;
        }
    }
    private Singleton() { }
}
```

## 💬 面试官常见追问
- "单例模式的缺点有哪些？" -> 全局状态导致测试困难、隐式依赖降低可读性、违反单一职责
- "Unity 中多个单例的初始化顺序怎么保证？" -> Script Execution Order 设置，或用依赖注入框架
- "单例的 DontDestroyOnLoad 有什么坑？" -> 重复实例需要销毁、场景回退时可能出现多实例
- "C++ 单例如何实现线程安全？" -> `std::call_once` + `std::once_flag`（C++11）、局部静态变量（C++11 保证线程安全）

## ⚠️ 我曾经的误区 / 网上常见错答
- **误区**：Unity 单例忘了 `Destroy(gameObject)`。多个实例同时存在导致逻辑混乱
- **误区**：双重检查锁定中的 `_instance` 不用 `volatile`。可能因为指令重排导致获取到未完全构造的对象
- **误区**：过度使用单例。不是所有 Manager 都必须是单例，可用依赖注入替代
