观察者模式可以发送一个信息，通知对信息感兴趣的对象，但不用关心对象会做什么。
一个简单的例子：当你从桥上掉下去，解锁成就。

可以通过简单的代码来触发：
```cpp
void Physics::updateEntity(Entity& entity)
{
  bool wasOnSurface = entity.isOnSurface();
  entity.accelerate(GRAVITY);
  entity.update();
  if (wasOnSurface && !entity.isOnSurface())
  {
    notify(entity, EVENT_START_FALL);
  }
}
```

这里使用了 `notify()` 函数来发送 `EVENT_START_FALL` 这个通知。

“成就系统注册它本身为观察者，这样当物理系统发出一个通知的时候，成就系统便会收到通知。然后它便会检查这个掉落的刚体是否是我们“坠落”的主角，并且检查它是否是从桥上面掉下去的。如果条件都满足，那么便会触发成就系统并放射礼花，吹响号角，并且这一切与物理系统完全解耦。“

## 1 How it works?
### 1.1 Observer
直接来看观察者代码，提供了一个接口。
```cpp
class Observer
{
public:
  virtual ~Observer() {}
  virtual void onNotify(const Entity& entity, Event event) = 0;
};
```

任何实现这个接口的类都是观察者，就如例子中的成就系统。这里具体实现了 `onNotify` 函数，当事件为 `EVENT_ENTITY_FELL` 时，解锁成就。
```cpp
class Achievements : public Observer
{
public:
  virtual void onNotify(const Entity& entity, Event event)
  {
    switch (event)
    {
    case EVENT_ENTITY_FELL:
      if (entity.isHero() && heroIsOnBridge_)
      {
        unlock(ACHIEVEMENT_FELL_OFF_BRIDGE);
      }
      break;

      // Handle other events, and update heroIsOnBridge_...
    }
  }

private:
  void unlock(Achievement achievement)
  {
    // Unlock if not already unlocked...
  }

  bool heroIsOnBridge_;
};
```

### 1.2 Subject
被观察者也是一个接口，有两个主要功能：
1. 首先它有一个观察者列表，可以让观察者在随时候命接收通知，并且暴露了一个可以修改观察者列表的公有API。
2. 发送通知

```cpp
class Subject
{
private:
	Observer* observers[MAX_OBSERVERS];
	int numOfObservers;

public:
	void addObserver(Observer* observer) 
	{
		// add to array...
	}
	
	void removeObserver(Observer* observer)
	{
		// remove from array...
	}
	
protected:
	void notify(const Entity& entity, Event event)
	{
		for (int i = 0; i < numOfObservers; i++)
		{
			observers[i]->onNotify(entity, event)
		}
	}
}
```

### 1.3 Observable Physics
现在，我们只需要将这些与物理引擎挂钩使得它能够发送通知，这样当成就达成的时候，我们的成就系统就可以接收到对应的通知。

```cpp
class Physics : public Subject
{
public:
  void updateEntity(Entity& entity);
};
```

现在，当物理系统做了一些事情后，他就会调用 `notify` 方法通知注册对象，遍历观察者列表，逐个给他们发送消息。

## 2 Cons?
### 2.1 Too Fast
“你不得不很小心，因为观察者模式是同步的。被观察者对象可以直接调用观察者们，这意味着，所有的观察者们都从它们的通知返回后被观察者才能继续工作，其中任何一个观察者对象都有可能阻塞被观察者对象。”

由于观察者模式实际上就是遍历列表调用函数，非常快。

### 2.2 Dynamic Allocation
因为是array，所以是动态内存分配，对一些算力要求高的场景不能普通的使用。因此可以使用链表来进行添加和删除。

代码举例（省略了其他方法）。为了实现这个，首先我们将数组从被观察者类中移除，并替换成一个指向链式列表中第一个观察者的指针：
```cpp
class Subject
{
  Subject()
  : head_(NULL)
  {}

  // Methods...
private:
  Observer* head_;
};
```

然后再给Observer增加一个指向链式列表中下一个观察者的指针：
```cpp
class Observer
{
  friend class Subject;

public:
  Observer()
  : next_(NULL)
  {}

  // Other stuff...
private:
  Observer* next_;
};
```
>这里的 `friend class Subject` 使 `Observer` 可以访问 `Subject` 中私有的、保护的方法。

添加 `Observer`：
```cpp
void Subject::addObserver(Observer* observer)
{
  observer->next_ = head_;
  head_ = observer;
}
```

移除 `Observer`：
```cpp
void Subject::removeObserver(Observer* observer)
{
  if (head_ == observer)
  {
    head_ = observer->next_;
    observer->next_ = NULL;
    return;
  }

  Observer* current = head_;
  while (current != NULL)
  {
    if (current->next_ == observer)
    {
      current->next_ = observer->next_;
      observer->next_ = NULL;
      return;
    }

    current = current->next_;
  }
}
```
>这里是单向链表，也可以使用更复杂的列表来帮助遍历

接下来只要遍历然后就可以发送信息了。
```cpp
void Subject::notify(const Entity& entity, Event event)
{
  Observer* observer = head_;
  while (observer != NULL)
  {
    observer->onNotify(entity, event);
    observer = observer->next_;
  }
}
```

但这种实现最大的缺陷是一个观察者只能观察一个 `Subject`，只适合资源受限的环境。
