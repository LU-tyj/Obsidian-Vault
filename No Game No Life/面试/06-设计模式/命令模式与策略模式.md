## 🎯 一句话结论（自测用）
> 命令模式：将请求封装为对象（Execute + Undo），支持撤销/重做/操作队列/回放。策略模式：定义一系列算法，运行时替换（如 AI 行为切换、伤害公式选择）。两者都实现开闭原则。

## ✅ 标准答案（结构化、可背诵，2分钟内讲完）
1. **命令模式**：
   - 将"请求"封装为命令对象，解耦调用者和执行者
   - 核心接口：`Execute()` + `Undo()`
   - 游戏应用：RTS 单位命令队列、回放系统（录像）、撤销/重做（关卡编辑器）
2. **策略模式**：
   - 定义一系列算法，使它们可以互相替换。算法的变化独立于使用它的客户端
   - 核心接口：不同策略实现同一接口
   - 游戏应用：AI 行为（巡逻/追击/逃跑）、伤害计算公式、资源加载策略（AssetBundle vs Resources）

## 🔍 详细解析

### 命令模式
```csharp
public interface ICommand
{
    void Execute();
    void Undo();
}

public class MoveCommand : ICommand
{
    private Unit unit;
    private Vector3 target;
    private Vector3 previousPosition;

    public MoveCommand(Unit u, Vector3 t)
    {
        unit = u;
        target = t;
    }

    public void Execute()
    {
        previousPosition = unit.Position;
        unit.MoveTo(target);
    }

    public void Undo()
    {
        unit.MoveTo(previousPosition);
    }
}

// 命令队列（RTS 游戏）
public class CommandQueue
{
    private Queue<ICommand> commands = new();
    private Stack<ICommand> undoStack = new();

    public void Enqueue(ICommand cmd)
    {
        cmd.Execute();
        commands.Enqueue(cmd);
        undoStack.Push(cmd);
    }

    public void Undo()
    {
        if (undoStack.Count > 0)
        {
            var cmd = undoStack.Pop();
            cmd.Undo();
        }
    }
}
```

**游戏回放系统原理**：记录所有命令及其时间戳，回放时按相同时间间隔依次 Execute。

### 策略模式
```csharp
// 策略接口
public interface IMovementStrategy
{
    Vector3 CalculateMove(Transform self, Transform target);
}

// 不同策略实现
public class PatrolStrategy : IMovementStrategy
{
    public Vector3 CalculateMove(Transform self, Transform target)
        => self.position + self.right * speed * Time.deltaTime;
}

public class ChaseStrategy : IMovementStrategy
{
    public Vector3 CalculateMove(Transform self, Transform target)
        => (target.position - self.position).normalized * speed * Time.deltaTime;
}

// 使用
public class EnemyAI : MonoBehaviour
{
    private IMovementStrategy moveStrategy;

    public void SetBehavior(IMovementStrategy strategy)
        => moveStrategy = strategy;

    void Update() => transform.position += moveStrategy.CalculateMove(transform, player);
}
```

### 命令模式 vs 策略模式
| | 命令模式 | 策略模式 |
|--|---------|---------|
| 目的 | 封装请求/操作 | 封装算法/行为 |
| 接口 | Execute + Undo | 策略方法 |
| 状态 | 可存储/可撤销 | 通常无状态 |
| 游戏案例 | 操作队列/回放 | AI 行为/伤害计算 |

## 💬 面试官常见追问
- "命令模式如何实现回放系统？" -> 存储每帧的输入命令序列，回放时按相同时间戳重新 Execute
- "策略模式和状态模式的区别？" -> 策略模式由外部主动切换（"我换一个算法"），状态模式由内部状态驱动自动切换（"我受伤了变成受伤状态"）
- "命令模式在哪里用到了面向对象的原则？" -> 开闭原则（新增命令无需改现有代码）、单一职责（每个命令类只负责一种操作）

## ⚠️ 我曾经的误区 / 网上常见错答
- **误区**：命令模式必须实现 Undo。不是所有命令都需要 Undo（如开枪），但标准接口最好提供。回放系统不需要 Undo
- **误区**：策略模式和状态模式实现一样所以是同一模式。虽然结构相似，但意图和使用方式不同
