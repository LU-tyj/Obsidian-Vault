# 网络同步面试题

## 一、TCP vs UDP

### Q1: TCP 和 UDP 的区别？

| 对比维度 | TCP | UDP |
|---------|-----|-----|
| 连接性 | 面向连接（三次握手） | 无连接 |
| 可靠性 | 可靠传输（丢包重发、流量控制、拥塞控制） | 不可靠，不保证送达 |
| 有序性 | 保证数据按序到达 | 不保证顺序 |
| 连接对象 | 仅支持一对一 | 支持一对一、一对多、多对多 |
| 传输效率 | 低（包头大、机制复杂） | 高（轻量级） |
| 应用场景 | 文件传输、MMO 状态同步 | 直播、视频、FPS 帧同步 |

### Q2: 为什么游戏中有时用 UDP 而不用 TCP？

TCP 的可靠性机制（确认重传、拥塞控制）会引入较大延迟。对于 FPS、MOBA 等实时性要求高的游戏，卡顿感明显。UDP 虽然不可靠，但可以在应用层补充可靠性机制（如 KCP 协议），实现低延迟下的可控可靠传输。

### Q3: TCP 黏包问题如何解决？
- 数据前加长度头，解析时按长度读取
- 使用固定分隔符
- 固定消息长度

## 二、帧同步 vs 状态同步

### Q4: 什么是帧同步（LockStep）？

**核心思想**：相同的输入 + 相同的时机 = 相同的表现

**工作机制**：
1. 每个客户端上传当前逻辑帧的操作（帧索引 + 操作指令）
2. 服务器仅广播转发所有客户端的操作
3. 每个客户端本地执行完整的逻辑运算

**实现要点**：
- 同步随机数种子
- 使用固定频率的逻辑帧（通常 66ms 一帧），不能用 Unity 的 Update
- 需自行实现物理（浮点数精度 -> 定点数）
- 保证所有客户端计算结果一致

**优点**：
- 单次同步数据量小（仅传输操作指令）
- 服务器压力小（只做转发）
- 易于实现录像回放
- 打击感、音效等细节反馈好

**缺点**：
- 反外挂能力弱（逻辑在客户端）
- 对网络要求极高，延迟抖动影响大
- 断线重连复杂（需逐帧回放到当前进度）

**适用场景**：格斗游戏、RTS、FPS、MOBA

### Q5: 什么是状态同步？

**核心思想**：服务器是权威计算端，客户端只做表现

**工作机制**：
1. 客户端发送操作给服务器
2. 服务器进行逻辑运算，计算出所有实体的新状态
3. 服务器将状态广播给所有客户端
4. 客户端根据收到的状态进行渲染表现

**优点**：
- 反外挂能力强（逻辑在服务端）
- 网络要求不高，允许较高延迟
- 玩家可随时加入进行中的战局

**缺点**：
- 传输数据量大（同步的是状态而非操作）
- 服务器压力大
- 打击感等细节反馈不如帧同步

**适用场景**：MMORPG、卡牌游戏、休闲竞技

### Q6: 核心区别一句话总结
> **帧同步同步的是"操作"，状态同步同步的是"结果"**

现代商业游戏常将两者结合使用。

## 三、帧同步深入

### Q7: 帧同步如何保证一致性？
1. 同步随机数种子（所有客户端从同一种子生成随机数）
2. 使用定点数（避免浮点精度问题）
3. 逻辑帧固定频率（不依赖 Unity 的 Update）
4. 逻辑与表现分离（表现可平滑插值）
5. 自行实现物理/碰撞（Unity 物理引擎为浮点数）

### Q8: 帧同步断线重连怎么做？
- 记录每帧操作序列
- 断线后从断点开始逐帧追帧回放
- 结合状态同步做快照（定期保存完整状态）
- 服务器可加速回放追赶进度

### Q9: 什么是状态帧同步？
按逻辑帧搜集变化的状态进行同步，结合帧同步的定时性和状态同步的数据结构。

## 四、网络协议与优化

### Q10: Protobuf 的优势？

| 对比 | Protobuf | JSON | XML |
|------|----------|------|-----|
| 序列化效率 | 极高 | 中 | 低 |
| 数据体积 | 极小（二进制） | 中 | 大 |
| 跨语言支持 | 优秀 | 优秀 | 优秀 |
| 版本兼容 | 支持（字段编号） | 弱 | 弱 |

游戏开发首选 Protobuf：体积小、速度快、跨语言、向前向后兼容。

### Q11: KCP 协议是什么？
- 基于 UDP 的可靠传输协议
- 优化了重传策略（比 TCP 激进的重传）
- 适合实时游戏（如 MOBA 每秒 15 帧）
- 牺牲 10%-20% 带宽换取 30%-40% 更低的延迟

### Q12: 心跳包的作用？
1. 检测连接是否存活
2. 维持 NAT 映射（防止路由器回收端口映射）
3. 检测网络延迟（RTT）

## 五、网络优化

### Q13: 网络抖动如何应对？
1. **客户端预测（Client-Side Prediction）**: 本地立即执行操作，收到服务器确认后校正
2. **插值平滑（Interpolation）**: 在两个已知状态间插值，让运动更平滑
3. **延迟补偿（Lag Compensation）**: 服务器回滚时间，基于玩家过去的视角判断命中

### Q14: 如何防外挂？
1. **服务端权威验证**: 关键逻辑在服务端执行
2. **操作合法性校验**: 检查操作频率和参数范围
3. **内存监控**: 检测内存修改
4. **行为检测**: AI 分析异常行为模式
