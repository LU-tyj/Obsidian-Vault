## 🎯 一句话结论（自测用）
> KCP 是基于 UDP 的可靠传输协议，比 TCP 更快但更激进——用 10%-20% 的额外带宽换 30%-40% 的延迟降低，适合 MOBA/FPS 等实时游戏。心跳包用于保持长连接的存活性（定时发送轻量包），防止 NAT 路由器回收端口映射。

## ✅ 标准答案（结构化、可背诵，2分钟内讲完）

**1. KCP 协议**：
- 基于 UDP 的可靠传输协议，在应用层实现
- **比 TCP 快的原因**：
  - 更激进的重传策略（选择性重传、快速重传），不等超时就重传
  - 不区分"拥塞丢包"和"链路丢包"——TCP 丢包就降速（保守），KCP 保持发送速率（激进）
  - 无慢启动——不需要从很小窗口开始增长
- **代价**：比 TCP 多消耗 10%-20% 带宽
- **适用场景**：实时对战游戏（如王者荣耀使用 KCP 确保帧同步操作指令的可靠传输）

**2. 心跳包（Heartbeat）**：
- 客户端定时（如每 5-10 秒）向服务器发送轻量级报文
- **三大作用**：
  1. **检测连接存活**：超时未收到心跳则认为连接已断，触发重连
  2. **维持 NAT 映射**：NAT 路由器会将不活跃的 UDP/TCP 映射回收（通常 30s-2min），心跳包保持映射不被回收
  3. **测量 RTT**：通过心跳包的收发时间差计算网络延迟

## 🔍 详细解析

**KCP vs TCP 的核心差异**：

| 特性 | TCP | KCP |
|------|-----|-----|
| 底层协议 | 自身 | UDP |
| 重传策略 | 超时重传 + 快重传 | 更激进的快重传 |
| 拥塞控制 | 严格（慢启动、AIMD） | 可配置的策略 |
| 带宽消耗 | 较低 | 高 10%-20% |
| 延迟 | 丢包时大幅增加 | 丢包时延迟增加较小 |
| 乱序处理 | 保证按序 | 可配置（有序/无序） |

**KCP 的流量控制**：
- KCP 有自己独立的流量控制，不依赖 TCP
- 支持设置发送/接收窗口大小
- 可配置为重传全部未 ACK 包（默认）或选择性重传

**心跳包的实现**：
```
Client:         Server:
  |--- PING --->|    (定时发送，带时间戳)
  |<-- PONG ----|    (立刻回包，带服务器时间)
  
RTT = (收到 PONG 的时间 - 发送 PING 的时间) / 2
```

## 💬 面试官常见追问
- "为什么心跳包叫'包'而不是'帧'？" -> 因为是基于 UDP/TCP 协议的数据包，不是视频/音频帧
- "NAT 映射回收是什么？" -> NAT 路由器为了节省资源，会回收一段时间（通常 30s-120s）没有通信的端口映射。一旦回收，外部无法再通过该端口访问内网设备。心跳包维持映射活跃

## ⚠️ 我曾经的误区 / 网上常见错答
- 误区：KCP 是 UDP 版的 TCP。KCP 和 TCP 的设计目标不同——KCP 以带宽换延迟，TCP 以延迟换带宽
- 误区：心跳包只是为了检测断线。维持 NAT 映射对于 P2P/NAT 穿透场景同样重要
