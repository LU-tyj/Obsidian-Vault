## 🎯 一句话结论（自测用）
> 观察者=一对多依赖通知。Csharp 实现：event/delegate（代码用）、UnityEvent（编辑器可配置）。事件中心用 Dictionary<EventType, Delegate>。场景切换必须注销事件，否则内存泄漏。

## ✅ 标准答案（结构化、可背诵，2分钟内讲完）
1. **定义**：主题（Subject）状态变化时，所有注册的观察者（Observer）自动收到通知。一对多依赖关系
2. **Csharp 实现方式**：
   - `event` + `delegate`：纯代码，性能好
   - `UnityEvent`：编辑器可序列化配置，有反射开销
   - 自定义 EventManager/MessageCenter：全局事件中心
3. **事件中心设计**：`Dictionary<EventType, List<Action>>` 存储，提供 Register / UnRegister / Trigger 方法
4. **关键注意事项**：场景切换/对象销毁时必须 UnRegister，否则事件中心持有引用导致内存泄漏

## 🔍 详细解析

### Csharp event/delegate 实现
```csharp
public class Player
{
    public event Action<int> OnHealthChanged;
    
    private int health;
    public int Health
    {
        get => health;
        set { health = value; OnHealthChanged?.Invoke(health); }
    }
}

// 订阅方
player.OnHealthChanged += UpdateHealthBar;
player.OnHealthChanged -= UpdateHealthBar;  // 必须注销！
```

### UnityEvent 实现
```csharp
using UnityEngine.Events;

public class Player : MonoBehaviour
{
    public UnityEvent<int> OnHealthChanged;
    
    private int health;
    public int Health
    {
        get => health;
        set { health = value; OnHealthChanged?.Invoke(health); }
    }
}
// 优点：可以在 Inspector 中拖拽绑定
// 缺点：有反射开销，稍慢
```

### 事件中心（EventManager）设计
```csharp
public class EventManager
{
    private static Dictionary<string, Delegate> eventDict = new();

    public static void Register<T>(string eventName, Action<T> handler)
    {
        if (eventDict.TryGetValue(eventName, out var d))
            eventDict[eventName] = Delegate.Combine(d, handler);
        else
            eventDict[eventName] = handler;
    }

    public static void UnRegister<T>(string eventName, Action<T> handler)
    {
        if (eventDict.TryGetValue(eventName, out var d))
        {
            eventDict[eventName] = Delegate.Remove(d, handler);
        }
    }

    public static void Trigger<T>(string eventName, T param)
    {
        if (eventDict.TryGetValue(eventName, out var d))
            (d as Action<T>)?.Invoke(param);
    }
}
```

### UnityEvent vs Csharp event
| | UnityEvent | Csharp event |
|--|-----------|----------|
| 序列化 | Inspector 可见配置 | 不可序列化 |
| 性能 | 较低（有反射/序列化开销） | 较高 |
| 适用 | 编辑器可视化配置 | 纯代码使用 |
| 绑定方式 | 拖拽赋值 | 代码 `+=` |

## 💬 面试官常见追问
- "UnityEvent 为什么性能较低？" -> 内部使用了序列化和反射来持久化 Inspector 绑定，调用路径比原生 delegate 长
- "如何避免事件中心的内存泄漏？" -> 对象 OnDestroy 时 UnRegister 所有注册的事件。或用弱引用（WeakReference）包装
- "事件中心和单例模式怎么结合？" -> EventManager 通常设计为单例，全局统一管理事件

## ⚠️ 我曾经的误区 / 网上常见错答
- **误区**：注册了事件但不注销。场景切换后对象已被销毁，但事件中心还持有引用 -> 内存泄漏 + 空回调
- **误区**：以为 UnityEvent 和 Csharp event 可以互换。UnityEvent 在 Destroy 后自动清理，Csharp event 不会
