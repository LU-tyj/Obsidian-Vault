## 🎯 一句话结论（自测用）
> vector=连续内存动态数组(扩容2倍)，list=双向链表，map=红黑树(O(logn)有序)，unordered_map=哈希表(O(1)无序)，priority_queue=二叉堆(O(logn)取最值)。

## ✅ 标准答案（结构化、可背诵，2分钟内讲完）
1. **vector**：连续内存，动态数组。扩容 1.5 倍或 2 倍。随机访问 O(1)，尾部插入均摊 O(1)，中间插入 O(n)
2. **list**：双向链表。任意位置插入删除 O(1)，随机访问 O(n)，不支持 `[]` 运算符
3. **deque**：双端队列，由多个固定大小数组块组成。头尾插入删除 O(1)，随机访问 O(1)，中间插入 O(n)
4. **map**：红黑树。key 有序存储，增删改查 O(logn)。适用于需要有序遍历的场景
5. **unordered_map**：哈希表 + 链地址法。平均 O(1)，最坏 O(n)。适用快速查找，不保证顺序
6. **priority_queue**：二叉堆（默认大顶堆）。push/pop O(logn)，top O(1)
7. **红黑树 vs AVL**：红黑树旋转少（插入删除快），AVL 严格平衡（查询更快）。STL map/set 选红黑树

## 🔍 详细解析

### vector 扩容机制
- VS 下通常 1.5 倍扩容，GCC 下 2 倍扩容
- 扩容时分配新内存 + 拷贝/移动元素 + 释放旧内存
- `emplace_back` vs `push_back`：emplace_back 原地构造，少一次拷贝/移动
- 面试追问"为什么扩容是 1.5 倍或 2 倍？" -> 均摊分析，保证 push_back 均摊 O(1)

### map（红黑树）详解
```cpp
// 红黑树性质：
// 1. 节点是红色或黑色
// 2. 根节点是黑色
// 3. 叶子节点（NIL）是黑色
// 4. 红色节点的子节点必须是黑色
// 5. 任一节点到叶子的所有路径黑色节点数相同
```
- 插入：先按 BST 插入（红色节点），再通过变色 + 旋转维持平衡（最多 2 次旋转）
- 删除：最多 3 次旋转

### unordered_map（哈希表）详解
- 底层：桶数组 + 链表（链地址法）
- 负载因子默认 ≈1.0（不同实现不同），超过时扩容 rehash
- 扩容后所有元素需要重新计算哈希并迁移
- 渐进式哈希：类似 Redis，避免一次性 rehash 的卡顿

### 容器选择指南
| 需求 | 推荐容器 |
|------|---------|
| 频繁随机访问 | vector / array |
| 频繁头尾插入 | deque |
| 频繁中间插入删除 | list |
| 快速查找 + 有序遍历 | map |
| 快速查找 + 无需顺序 | unordered_map |
| 需要最大值/最小值 | priority_queue（堆） |

## 💬 面试官常见追问
- "emplace_back 和 push_back 的区别？" -> push_back 先构造临时对象再移动；emplace_back 原地构造，更高效
- "红黑树和 AVL 树场景选择？" -> 查询多选 AVL（更平衡），插入删除多选红黑树（旋转少）
- "为什么不用哈希表替代红黑树？" -> 哈希表无法有序遍历、无法做范围查询（lower_bound/upper_bound）

## ⚠️ 我曾经的误区 / 网上常见错答
- **误区**：vector 扩容一定 2 倍。实际取决于编译器（GCC 2 倍，VS/Clang 1.5 倍）
- **误区**：list 可以随机访问。list 不支持 `[]` 运算符，只能通过迭代器遍历
- **误区**：说 priority_queue 底层是堆即可，但说不清什么是堆。需要能解释二叉堆的数组存储方式
