## 使用方法

1. 终端 `cd ~/Obsidian/NGNL/` 后启动 `claude`（或直接把本文件存成该目录下的 `CLAUDE.md`，之后每次在这个目录起会话都会自动生效）。
2. 把「三、可直接粘贴的提示词」整段发给 Claude Code，它会用 `Task` 工具拆分出多个 subagent 并行执行。
3. 抓取量大时建议分两轮发送：先发「阶段一」跑完爬取，检查 raw 目录质量后，再发「阶段二」做整理归档——避免脏数据被直接汇总进知识库。

## 一、目录与分类规范

### 1.1 `raw/面经/`：只存档，不加工

按【来源平台】分类，保留原始信息，方便溯源和去重校验；不要求排版精美，要求**信息完整、来源可查**。

```
raw/面经/
├── _抓取日志.md              # 每次抓取的时间/来源/条数/负责agent，追加写入
├── 牛客网/
│   └── 2026-07-03_网易互娱Unity客户端.md
├── 知乎/
├── 博客员/
├── GitHub面经/
├── 小红书/
└── BOSS直聘_面试评价/
```

原始文件统一 frontmatter：

```yaml
---
source_platform: 牛客网
source_url: https://...
crawl_date: 2026-07-03
crawl_agent: agent-nowcoder
company_mentioned: [网易互娱, 网易雷火, 网易伏羲]
position: Unity客户端开发
raw: true
---
```

> raw 层的每条面经原文尽量保留「原始问答」+「楼主补充说明」，不要在这一层就做归纳，归纳放在第二层做，避免信息丢失。

### 1.3 单篇笔记模板（核心）

### 1.4 复习机制

- `00-总览/复习计划.md` 用表格记录每篇笔记的 `next_review` 日期，按 1/3/7/15/30 天间隔滚动。
- `status` 字段三态足够：`new`（新收录待学）→ `reviewing`（已学至少一遍）→ `mastered`（可脱稿讲清楚）。
- `高频TOP50.md` 只做链接聚合，不重复正文，避免内容双写导致后续不同步。

## 二、多 Subagent 分工设计

**阶段一・爬取（并行，按「来源」拆分，互不干扰、可并发写文件）**

- Agent-牛客网：搜索"网易互娱 Unity 客户端 面经/面试"相关帖子，抓取问答与楼主经验贴
- Agent-社区（知乎/掘金）：抓取技术社区上的网易互娱面试复盘、技术长文
- Agent-开源仓库（GitHub）：搜索 Unity/游戏客户端面试题合集类仓库
- Agent-社媒（小红书/BOSS直聘评价）：抓取更口语化的面试流程/体验类信息（部门、氛围、轮次）

**阶段二・整理（按「知识分类」拆分，各自读取全部 raw 文件后产出对应目录笔记）**

- Agent-C#与Unity引擎：产出 01、02 目录笔记
- Agent-图形学与计算机基础：产出 03、04 目录笔记
- Agent-算法与设计模式：产出 05、06、10 目录笔记
- Agent-系统设计与网易专项：产出 08、09 目录笔记，并更新 `00-总览/网易互娱情报.md`
- 最后由主对话（非 subagent）统一更新 `MOC-面试总览.md` 和 `高频TOP50.md`，避免多个 agent 同时写同一文件产生冲突。

## 三、可直接粘贴给 Claude Code 的提示词

```
你现在是我的"网易互娱 Unity 客户端开发"面试知识库整理助手。请使用 Task 工具拆分 subagent 完成以下两阶段任务。

【背景】
- 目标岗位：网易互娱 Unity 游戏客户端开发（含校招/社招/实习）
- 我的 demo 技术栈是 Unity + C#
- 输出必须遵循下方"目录规范"和"笔记模板"，不要自创格式

【目录规范】
raw 层：~/Obsidian/NGNL/raw/面经/{来源平台}/{日期}_{主题}.md
整理层：~/Obsidian/NGNL/No Game No Life/面试/{分类}/{知识点}.md
分类固定为：01-C#语言基础、02-Unity引擎原理、03-图形学与渲染、04-计算机基础(含操作系统/计算机网络/网络同步)、05-数据结构与算法、06-设计模式、07-性能优化与内存管理、08-系统设计与项目经验、09-网易互娱专项、10-算法手撕高频题

【阶段一：并行爬取（先只做这一步）】
请启动 4 个并行 subagent，分别负责：
1. 牛客网：搜索"网易互娱/网易雷火/网易伏羲 Unity客户端 面经"，抓取近1-2年的面试帖，问答原文+楼主补充完整保留
2. 知乎/掘金：搜索网易互娱 Unity 客户端面试相关的技术复盘长文
3. GitHub：搜索 Unity/游戏客户端方向的面试题合集类开源仓库，摘取网易互娱相关或通用高频八股题
4. 小红书/BOSS直聘评价类：抓取偏"面试流程/部门方向/面试官风格"的经验分享

每个 subagent 完成后：
- 按"来源平台"分类写入 raw/面经/ 对应子目录，每个来源一个或多个 md 文件
- frontmatter 必须包含 source_platform / source_url / crawl_date / company_mentioned / position / raw: true
- 写入前检查该来源目录下是否已有相同 URL，避免重复抓取
- 完成后在 raw/面经/_抓取日志.md 追加一行记录（时间、来源、条数、agent名）

全部完成后给我一个汇总：各来源抓到多少条、大致覆盖了哪些知识分类，我确认后再进行阶段二。

【阶段二：分类整理归档（我确认raw内容质量后再执行）】
请启动多个 subagent，按知识分类拆分（C#与Unity引擎 / 图形学与计算机基础 / 算法与设计模式 / 系统设计与网易专项），每个 subagent：
- 通读 raw/面经/ 下的全部原始文件，抽取属于自己负责分类的问答
- 对同一知识点在不同来源中反复出现的问题做合并去重，出现次数体现在 frequency 字段（⭐/⭐⭐/⭐⭐⭐）
- 按"单篇笔记模板"（一句话结论/标准答案/详细解析/常见追问/易错点/关联知识点/原始出处）在对应分类目录下产出原子笔记，一个知识点一篇
- 笔记之间用双链互相关联
- 完成后向我报告本分类产出了多少篇笔记、其中标记为⭐⭐⭐高频的有哪些

全部分类 agent 完成后，请你（不要用 subagent，主对话直接做）：
1. 更新 00-总览/MOC-面试总览.md，按分类列出所有新增笔记的链接
2. 更新 00-总览/高频TOP50.md，汇总全库 frequency 为⭐⭐⭐的题目
3. 更新 00-总览/网易互娱情报.md，汇总面经中提到的网易互娱面试流程、部门方向（雷火/伏羲等）、面试官风格等信息

开始执行阶段一。
```

## 说明

- 阶段一/二分开发送是为了让你能在正式写入知识库前检查抓取质量（面经类内容鱼龙混杂，人工把一道关容易，但让 agent 自动把关不可靠）。
- 如果你希望某几个分类优先整理（比如先冲图形学和网易专项），可以在阶段二提示词里直接删掉不需要的 subagent 分工，只跑你要的那几个。
- 后续每次有新的面经来源，可以只重跑"阶段一"里的某个 agent + 增量版"阶段二"（只处理 raw 里 crawl_date 晚于上次整理时间的新文件），避免全量重新整理。
