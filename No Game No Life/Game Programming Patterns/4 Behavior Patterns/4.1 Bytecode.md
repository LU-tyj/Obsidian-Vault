_Give behavior the flexibility of data by encoding it as instructions for a virtual machine._

unity 中inspector的数据修改相当于改变config.json文件，和Bytecode 直接修改代码不同

## 1 Motivation
为了追求游戏的性能，我们会使用cpp、c等重型语言，但随着代码量的增长，我们每次一个简单的修改需要进行长时间的编译。

如果我们想要提供模组，让用户可以创造自己的法术，如果这些法术都在代码里，意味着玩家需要一个完整的编译工具来构建游戏，而且如果制作的法术存在bug，可能会导致其他玩家的机器上引发游戏崩溃。

为了实现这个目的，我们需要把法术从游戏核心中分离，将其存储为一种“数据”，用文件中的字节表示法术的behavior，现在思考的就是如何**执行**这些数据。
>最经典的方法是解释器模式，比如 $(1+2) * (3-4)$。
>首先**解析器**将其每个对象（包括运算符）进行封装，解析这些对象，变成一个抽象的语法树（如下图）
>然后解释器负责额执行这个语法树（与如何创建无关），即定义每个 Expression 的类，比如`Expression`, `NumberExpression`, `AdditionExpression`，每个Expression有`evaluate`函数。![[InterpretAbstractTree.png]]
>但很不幸的是，这个模式有很多的问题：占用大量的内存、数据缓存、要从磁盘加载它需要实例化然后串联成小对象……
>总之就是太慢了，太大了

我们想要通过机械码来提高效率，但又不能让用户直接写机械码，容易出现安全性问题，因此我们定义了自己的**虚拟机器码**，在游戏中实现一个执行它的小型模拟器，这个模拟器就称为**虚拟机(VM)**

现在才开始介绍这个模式：==通过指令集定义了一套可以执行的底层操作，一系列指令被编码成字节序列。虚拟机逐条执行指令栈上的这些指令。通过组合指令，即可完成很多高级的行为。==

---
## 2 When to use it
- 编辑语言太底层了，编写起来繁琐易错
- 因编译时间太长或工具问题，导致迭代缓慢
- 安全性太依赖编码者，为了防止程序崩溃，得把它们从代码库移动到安全沙箱

## 3 Sample
就延续我们在 [[#1 Motivation]] 中的魔法例子，我们先创建一个指令集。

### 3.1 Spell API
首先我们需要知道有什么法术API
```cpp
// Spell Behaviors
void setHealth(int wizard, int amount);
void setWisdom(int wizard, int amount);
void setAgility(int wizard, int amount);

// Effects Behavior
void playSound(int soundId);
void spawnParticles(int particleType);
```

### 3.2 Instructions
由此我们构建法术指令集，即将上面的API转换成数据可控的形式。假设所有 `set---()` 函数都会影响玩家控制的法师并强化其对应属性（以此类推）。这样，法术其实就是一系列指令的集合，我们可以通过枚举来创建。
```cpp
enum Instruction
{
  INST_SET_HEALTH      = 0x00,
  INST_SET_WISDOM      = 0x01,
  INST_SET_AGILITY     = 0x02,
  INST_PLAY_SOUND      = 0x03,
  INST_SPAWN_PARTICLES = 0x04
};
```
当我们执行一条命令时，我们首先找到对应的基础属性，然后调用法术的API
```cpp
switch (instruction)
{
  case INST_SET_HEALTH:
    setHealth(0, 100);
    break;

  case INST_SET_WISDOM:
    setWisdom(0, 100);
    break;

  case INST_SET_AGILITY:
    setAgility(0, 100);
    break;

  case INST_PLAY_SOUND:
    playSound(SOUND_BANG);
    break;

  case INST_SPAWN_PARTICLES:
    spawnParticles(PARTICLE_FLAME);
    break;
}
```

这样之后我们就可以把它封装到一个VM中，像下面代码所示释放法术。
```cpp
class VM
{
public:
  void interpret(char bytecode[], int size)
  {
    for (int i = 0; i < size; i++)
    {
      char instruction = bytecode[i];
      switch (instruction)
      {
        // Cases for each instruction...
      }
    }
  }
};
```

但这个简单的 VM 不够灵活，没法定义一个能够有具体数值的法术，只有音效。

### 3.3 A Stack Machine
执行一个复杂的潜逃表达式，需要从最内侧的子表达式开始，将其结果传递给外层表达式，直到计算完毕。解释器模式采用的是构建一个嵌套对象树，但由于我们的数据是展平的，以及需要更快的运行速度，因此我们 得通过指令的顺序去控制，采用和cpu相同的 stack 方法。

一个 stack machine 需要一个 internal stack of values（存储计算的中间过程数值），以及数值进栈出栈的方法。当一段**数据要求指令**逐一执行下去时，实际上就是在**遍历堆栈**。
```cpp
class VM
{
public:
  VM()
  : stackSize_(0)
  {}

  // Other stuff...

private:
  void push(int value)
  {
    // Check for stack overflow.
    assert(stackSize_ < MAX_STACK);
    stack_[stackSize_++] = value;
  }

  int pop()
  {
    // Make sure the stack isn't empty.
    assert(stackSize_ > 0);
    return stack_[--stackSize_];
  }
  
  static const int MAX_STACK = 128;
  int stackSize_;
  int stack_[MAX_STACK];
};
```

当某个指令需要输入参数时，它会按照下面的方式堆栈中弹出来
```cpp
switch (instruction)
{
  case INST_SET_HEALTH:
  {
    int amount = pop();
    int wizard = pop();
    setHealth(wizard, amount);
    break;
  }

  case INST_SET_WISDOM:
  case INST_SET_AGILITY:
    // Same as above...

  case INST_PLAY_SOUND:
    playSound(pop());
    break;

  case INST_SPAWN_PARTICLES:
    spawnParticles(pop());
    break;
}
```

我们知道stack时如何运行指令了，现在我们要学习如何向堆栈中添加数值，这时我们需要一个新的指令：**字面值**。表示一个字面上的整数数值。但问题也还存在，这个字面值指令又从哪里获取数值呢？

我们可以将数字直接塞进字节数组，然后用下面的代码来定义字节数指令。
```cpp
case INST_LITERAL:
{
  // Read the next byte from the bytecode.
  int value = bytecode[++i]; 
  push(value);
  break;
}
```
读取了字节流码中的下一个字节，将它作为一个数值写入堆栈
>字节流码就是代码中的 `bytecode` 数组，其中包含了一堆指令
>
>这里的意思是把数值存储在 字面值 指令的下一位（形如 `[..., 0x05, 123, ...]`，遍历执行时，解释器先看到 "INST_LITERAL"，然后会读取下一个字节，并将其压入堆栈中。
>
>举个例子：当回复生命的时候，会先重复上面的字面值指令，将 0 和 10 压入堆栈中，然后执行 "INST_SET_HEALTH" 指令，会从栈中取出这两个value并存储到 `wizard` 和 `amount` 中，然后利用这两个参数进行 `setHealth`![[SampleofStack.png]]

这样我们就实现了进行数值的改变，但我们没法做到比如回复巫师一半血量的操作。
我们要制定法术的计算规则，而不仅仅是数值。

### 3.4 Behavior = Composition
为了实现上文提及的操作，我们还需要加上能够读取当前状态的指令
```cpp
case INST_GET_HEALTH:
{
  int wizard = pop();
  push(getHealth(wizard));
  break;
}

case INST_GET_WISDOM:
case INST_GET_AGILITY:
  // You get the idea...
```
先从栈中找到巫师，将其出栈，然后再获取目的状态，再将其入栈。

接下来我们为了组合，我们还需要算术，下面是一个简单的 1+1：
```cpp
case INST_ADD:
{
  int b = pop();
  int a = pop();
  push(a + b);
  break;
}
```

这样之后我们可以处理一些深层嵌套的算术表达式了。
比如要制作一个法术，能够将玩家巫师的生命设定成他们敏捷值和智力值的平均值：
```cpp
setHealth(0, getHealth(0) + (getAgility(0) + getWisdom(0)) / 2);
```

解释器会将这段代码解释为 bytecode，然后遍历执行

手工求值过程：
1. 取出并保存巫师当前生命值；
2. 取出并保存巫师当前敏捷度；
3. 取出并保存巫师当前智力值；
4. 取出保存的命解读和智力值，将它们相加并保留结果；
5. 将结果除以2后保存结果；
6. 取出巫师的生命值加到结果里面；
7. 取出结果赋值给巫师的生命属性。

### 3.5 A Virtual Machine
我们现在有一个小VM，实现也只是一个 stack、一个循环遍历、一个switch。
由于字节码没法深入引擎的各个部分，所以我们能成功地沙箱化。

我们要通过控制堆栈尺寸来限制可用内存，避免 stack overflow，甚至可以限制执行时间。

## 4 Design Decisions
### 4.1 指令如何访问堆栈
字节码虚拟机有两大风格：基于栈和基于寄存器。
前者总是操作栈顶，后者可以从更深层中读取输入。

- **基于栈的VM**
	指令很小，代码生成更简单，但指令数更多
- **基于寄存器的VM**
	指令更大（要记录参数在栈中的偏移量，例如Lua的VM每个指令占用32bits，其中6位用来存储指令类型，剩下用来存储参数
	指令更少，因为每个指令可以做到更多事情

前者易于实现，后者效率更高

### 4.2 应该有哪些指令
- **外部基本操作**：位于虚拟机之外、在引擎内部的，就像第三部分举例到的 API；
- **内部基本操作**：操作虚拟机的内部的值，就比如上面加法的例子；
- **控制流**：例子中没有，但如果想让指令有选择地执行或循环重复执行，就需要控制流。举例来说就是 `goto`，更改当前执行位置
>y1s1就是基本的编程语言语法

### 4.3 数值应该如何表示
上面的例子只展示了 int 类型。其他的话需要添加标签，也是动态类型语言（py）通用的形式。

每个值由两个部分组成。
1. 标签——用来标志所存数据类型的枚举值
2. 数值——根据标签解析数值
```cpp
enum ValueType
{
  TYPE_INT,
  TYPE_DOUBLE,
  TYPE_STRING
};

struct Value
{
  ValueType type;
  union
  {
    int    intValue;
    double doubleValue;
    char*  stringValue;
  };
};
```
