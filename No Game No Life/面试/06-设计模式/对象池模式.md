## 🎯 一句话结论（自测用）
> 对象池复用频繁创建/销毁的对象，减少 GC 压力。Unity 中用 List/Stack 维护 inactive GameObjects。预热（Pre-warm）+ 用 UnityEngine.Pool.ObjectPool（Unity 2021+）。

## ✅ 标准答案（结构化、可背诵，2分钟内讲完）
1. **核心思想**：预先创建一定数量对象，使用时取出（激活），用完放回（失活），避免频繁 Instantiate/Destroy 造成的 CPU 和 GC 开销
2. **基本实现**：Stack/List 存储未使用对象。Get() 取一个（不够则扩容），Release() 重置状态后放回
3. **Unity 实现要点**：
   - 预热（Pre-warm）：游戏开始时预先生成 N 个对象
   - 维护 inactive 的 GameObject 列表
   - Release 时调用 `SetActive(false)`，重置位置/状态
4. **进阶**：`UnityEngine.Pool.ObjectPool<T>`（Unity 2021+）、泛型对象池

## 🔍 详细解析

### 基本泛型对象池
```csharp
public class ObjectPool<T> where T : new()
{
    private Stack<T> pool = new Stack<T>();

    public T Get()
    {
        return pool.Count > 0 ? pool.Pop() : new T();
    }

    public void Release(T obj)
    {
        // 重置对象状态
        if (obj is IPoolable poolable)
            poolable.Reset();
        pool.Push(obj);
    }
}

public interface IPoolable
{
    void Reset();
}
```

### Unity GameObject 对象池
```csharp
public class GameObjectPool : MonoBehaviour
{
    [SerializeField] private GameObject prefab;
    [SerializeField] private int prewarmCount = 10;
    private Queue<GameObject> pool = new Queue<GameObject>();

    void Start()
    {
        for (int i = 0; i < prewarmCount; i++)
            CreateAndEnqueue();
    }

    private void CreateAndEnqueue()
    {
        var obj = Instantiate(prefab, transform);
        obj.SetActive(false);
        pool.Enqueue(obj);
    }

    public GameObject Get()
    {
        if (pool.Count == 0) CreateAndEnqueue();
        var obj = pool.Dequeue();
        obj.SetActive(true);
        return obj;
    }

    public void Release(GameObject obj)
    {
        obj.SetActive(false);
        obj.transform.SetParent(transform);
        pool.Enqueue(obj);
    }
}
```

### UnityEngine.Pool（Unity 2021+）
```csharp
using UnityEngine.Pool;

public class BulletManager : MonoBehaviour
{
    [SerializeField] private Bullet bulletPrefab;
    private ObjectPool<Bullet> pool;

    void Start()
    {
        pool = new ObjectPool<Bullet>(
            createFunc: () => Instantiate(bulletPrefab),
            actionOnGet: bullet => bullet.gameObject.SetActive(true),
            actionOnRelease: bullet => bullet.gameObject.SetActive(false),
            actionOnDestroy: bullet => Destroy(bullet.gameObject),
            defaultCapacity: 10, maxSize: 100
        );
    }

    public Bullet GetBullet() => pool.Get();
    public void ReleaseBullet(Bullet bullet) => pool.Release(bullet);
}
```

### 对象池的关键设计点
| 要点 | 说明 |
|------|------|
| 预热容量 | 预测最大同时使用量，避免运行时频繁扩容 |
| 状态重置 | Release 时恢复默认状态，避免上次使用后的"脏数据" |
| 上限容量 | 防止无限增长撑爆内存 |
| 分帧创建 | 预热数量很大时分帧 Instantiate，避免卡顿 |

## 💬 面试官常见追问
- "对象池的预热数量怎么定？" -> 根据场景最大同时出现的对象数量 + 20% buffer。可以运行时统计动态调整
- "对象池满了（达到上限）怎么办？" -> 返回 null / 复用最早的对象（LRU）/ 拒绝请求并告警
- "对象池和工厂模式的关系？" -> 对象池内部可以用工厂模式创建新对象（当池为空时）

## ⚠️ 我曾经的误区 / 网上常见错答
- **误区**：对象池不需要重置状态。对象复用时可能还保留上次的数据（位置/血量/动画状态），导致 bug
- **误区**：对象池越多越好。过多的对象池预占内存，预热量需要根据实际需求权衡
- **误区**：只用 Stack 就够了。实际需要维护"已借出"列表来追踪泄漏（借了不还的对象）
