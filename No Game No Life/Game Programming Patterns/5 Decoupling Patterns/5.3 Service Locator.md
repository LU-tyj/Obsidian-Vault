_Provide a global point of access to a service without coupling users to the concrete class that implements it._

## 1 Motivation
有些对象或者系统可能会出现在游戏的各个角落，比如声音系统，当你打开界面时，当你攻击时，当敌人走路时，当发生撞击时……如果这些场景每次都要调用我们的音频系统，不管是[[2.5 Singleton Pattern]]单例模式，还是静态函数，都不可避免出现很多的耦合。而且当你对原本的系统进行改变，那么需要修改其他所有的系统（比如将AudioSystem修改名字为FMODAudioSystem）。

这里有一个更好的解决方法，准备一个电话簿，其他想要联系我的人能通过查找我的名字来得到当前的电话号码，当我们换电话号码时，只需要更新电话簿，就可以让其他所有人都知道我们新的号码了。

服务定位器模式：一个服务类为一系列操作定义了一个抽象的接口。一个具体的服务提供器实现这个接口。一个单独的服务定位器（电话薄）通过查找一个合适的提供器来提供这个服务的访问，它同时屏蔽了提供器的具体类型和定位这个服务的过程。

---

## 2 How & When to use it
不可避免的是，这个服务定位器是全局能访问的，就和单例模式中提及的缺点一样。这个模式用起来像一个灵活、可配置的单例模式。

使用的关键难点在于，它要有所依赖，并且在运行时才连接起来（代码阅读性减少）。而且定位服务可能也会失败（不一定能找到服务），以及要保证在任何情况下都必须正确工作（比如一个类只希望在游戏循环中的仿真起到作用，那么就不能在渲染期间进行服务）

---

## 3 Sample
就继续音频系统的举例。
### 3.1 Service
我们要把音频api暴露给定位器，首先我们先实现音频暴露的接口。
```cpp
class Audio
{
public:
  virtual ~Audio() {}
  virtual void playSound(int soundID) = 0;
  virtual void stopSound(int soundID) = 0;
  virtual void stopAllSounds() = 0;
};
```

### 3.2 The service provider
这里是音频代码的具体实现（这里意会）
```cpp
class ConsoleAudio : public Audio
{
public:
  virtual void playSound(int soundID)
  {
    // Play sound using console audio api...
  }

  virtual void stopSound(int soundID)
  {
    // Stop sound using console audio api...
  }

  virtual void stopAllSounds()
  {
    // Stop all sounds using console audio api...
  }
};
```

剩下的就是服务定位器了，将我们的接口和具体的实现绑定在一起。

### 3.3 Locator
这里，我们除了要实现一个简单的服务定位器，来提供服务，还要解决上面所提及的难点，即解决找不到服务、提供正确的服务的问题。

首先，为了防止找不到服务，我们要先定义一个空服务：
```cpp
class NullAudio: public Audio
{
public:
  virtual void playSound(int soundID) { /* Do nothing. */ }
  virtual void stopSound(int soundID) { /* Do nothing. */ }
  virtual void stopAllSounds()        { /* Do nothing. */ }
};
```

然后就可以写我们的Locator了
```cpp
class Locator
{
public:
  static void initialize() { service_ = &nullService_; }

  static Audio& getAudio() { return *service_; }

  static void provide(Audio* service)
  {
    if (service == NULL)
    {
      // Revert to null service.
      service_ = &nullService_;
    }
    else
    {
      service_ = service;
    }
  }

private:
  static Audio* service_;
  static NullAudio nullService_;
};
```
>这里我们使用 `getAudio` 返回我们的服务，让其他系统都可以调用；使用 `provide` 绑定服务，实心啊定位的效果。而且当我们没有提供服务时，我们的定位器会自动返回空服务。

当游戏开始时，我们只需要如下的代码就可以绑定：
```cpp
ConsoleAudio *audio = new ConsoleAudio();
Locator::provide(audio);
```

然后使用的话：
```cpp
Audio* audio = Locator::getAudio();
audio->playSound(VERY_LOAD_BANG);
```

开发中，我们可以给一个null服务，这样就可以节约内存和CPU周期，也不用充满音效。

### 3.4 Logging Decorator
有时候AI程序员需要音效的log日志，但是大部分情况下不需要，只需要AI的log日志，必须过滤掉各自的信息。为了实现日志的选择性开启，我们可以使用装饰器模式。让我们用另一个音频服务提供器来实现：
```cpp
class LoggedAudio : public Audio
{
public:
  LoggedAudio(Audio &wrapped)
  : wrapped_(wrapped)
  {}

  virtual void playSound(int soundID)
  {
    log("play sound");
    wrapped_.playSound(soundID);
  }

  virtual void stopSound(int soundID)
  {
    log("stop sound");
    wrapped_.stopSound(soundID);
  }

  virtual void stopAllSounds()
  {
    log("stop all sounds");
    wrapped_.stopAllSounds();
  }

private:
  void log(const char* message)
  {
    // Code to log message...
  }

  Audio &wrapped_;
};
```

当一个程序需要音频日志，我们只需要下面的代码就好了：
```cpp
void enableAudioLogging()
{
  // Decorate the existing service.
  Audio *service = new LoggedAudio(Locator::getAudio());

  // Swap it in.
  Locator::provide(service);
}
```
其他就可以用普通的服务

Unity框架把这个模式和组件 模式（第14章）结合起来，并使用在了GetComponent() 方法中。
