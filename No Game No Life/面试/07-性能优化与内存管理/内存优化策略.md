## 🎯 一句话结论（自测用）
> 内存优化八大策略：贴图压缩（ASTC > ETC2 > PVRTC）、关闭 Read/Write Enabled、透明通道分离、降低模型面数和骨骼数、控制 Resources 文件夹大小、按需加载（AssetBundle/Addressables）、Lightmap 替代实时光、控制 RenderTexture 分辨率。

## ✅ 标准答案（结构化、可背诵，2分钟内讲完）
1. **贴图压缩**：移动端使用 ASTC（iOS 全系 + Android 高端）> ETC2（Android 标配）> PVRTC（iOS 旧版），根据平台选择。带透明通道的贴图分开压缩为两张（RGB + Alpha），可用 ETC 压缩 RGB 部分。
2. **关闭 Read/Write Enabled**：开启此选项会让贴图在 CPU 内存中保留一份可读写副本，内存翻倍。非必须（如不运行时修改贴图像素）应关闭。
3. **降低模型复杂度**：减少面数、骨骼数（蒙皮网格开销随骨骼数增长）、BlendShape 数量。
4. **Resources 文件夹控制**：所有 Resources 下的资源无论用不用都会打包进最终文件。只放必须通过 Resources.Load 加载的资源，大部分使用 AssetBundle/Addressables。
5. **按需加载**：AssetBundle / Addressables，不一次性加载所有资源，控制内存峰值。场景切换时卸载前一个场景的 Bundle。
6. **Lightmap 替代实时光**：静态物体使用烘焙光照贴图，不占用实时光照计算和 ShadowMap 内存。
7. **控制 RenderTexture 分辨率**：RenderTexture 在显存中分配，高分辨率 = 大内存占用。
8. **音频**：长音频使用 Streaming（流式加载），短音效使用 Decompress On Load 或 Compressed In Memory。

## 🔍 详细解析

### 贴图压缩格式对比
| 格式 | 比特率 | 平台 | 特点 |
|------|--------|------|------|
| ASTC | 可配置 | iOS 全系/Android 高端 | 最高压缩质量比 |
| ETC2 | 4bpp | Android 标配 | 支持 Alpha |
| ETC | 4bpp | Android 全系 | 不支持 Alpha，需分离通道 |
| PVRTC | 2-4bpp | iOS 旧版 | 要求方形、2 的幂 |
| DXT5 | 8bpp | PC | Windows 桌面端 |

### 透明通道分离
- 问题：带 Alpha 的贴图必须用 RGBA 压缩格式（体积大）
- 解决方案：拆分为 RGB 图（用 ETC 压缩，体积小）+ Alpha 图（用 ETC 压缩）
- Shader 中采样两张贴图，组合还原

### Resources 与 AssetBundle 内存差异
| 对比维度 | Resources | AssetBundle |
|---------|-----------|-------------|
| 卸载粒度 | 只能全局 UnloadUnusedAssets | 按包粒度卸载 |
| 内存控制 | 所有资源驻留，无法按需释放 | 加载/卸载精细控制 |
| 启动内存 | 大（全部打包） | 小（按需加载） |

### RenderTexture 内存计算
- 1920x1080, RGBA32: 1920 x 1080 x 4 bytes ≈ 8MB
- 如果有多个 RT（后处理链、阴影贴图等），内存叠加会非常可观

## 💬 面试官常见追问
- **如何确定哪些资源占用内存大？** → Profiler Memory 面板、Memory Profiler 抓取快照对比
- **贴图 Read/Write 什么时候必须开启？** → 运行时修改像素数据（如 Texture2D.SetPixels）、读取像素做计算
- **Resources 和 StreamingAssets 的区别？** → Resources 资源经过 Unity 序列化由引擎管理；StreamingAssets 保留原始格式，通过文件路径读取，适合视频等大文件

## ⚠️ 我曾经的误区 / 网上常见错答
- 误区：ASTC 可以替代一切。ASTC 压缩时间长、部分旧设备不支持，需合理配置 Fallback
- 误区：所有贴图都压到最小。UI 贴图需要较高精度，过度压缩导致模糊
