## 🎯 一句话结论（自测用）
> 帧同步的一致性依赖于五大要素：同步随机数种子、使用定点数（避免浮点误差）、固定频率逻辑帧（不依赖 Unity Update）、逻辑与表现分离、自行实现确定性物理。断线重连通过记录操作序列逐帧回放 + 定期状态快照来实现。

## ✅ 标准答案（结构化、可背诵，2分钟内讲完）

**帧同步五大一致性保证要素**：

1. **同步随机数种子**：
   - 所有客户端使用相同的随机数种子
   - 每次需要随机时从同一序列取数
   - 确保"随机"结果在所有客户端上完全一致

2. **使用定点数（Fixed Point）**：
   - 浮点数（float/double）在不同平台/编译器的运算结果可能不同（如 NaN 处理、舍入模式）
   - 定点数将小数用整数表示（如 1.5 = 1500，精度 0.001），运算结果跨平台完全一致
   - 常用于位置、速度、碰撞检测等需要严格一致的运算

3. **固定频率逻辑帧**：
   - 逻辑帧频率固定（如每秒 15 帧 = 66ms/帧），不能使用 Unity 的 `Update`（受渲染帧率影响）
   - 使用固定时间步长 `FixedUpdate` 或自行实现固定间隔逻辑循环
   - 保证"相同的时机"——所有客户端在同一逻辑帧执行相同操作

4. **逻辑与表现分离**：
   - 逻辑层：确定性计算，帧同步核心
   - 表现层：渲染/动画/音效，可平滑插值
   - 表现层允许因渲染帧率不同而"看起来不同"，但逻辑层结果必须一致

5. **自行实现确定性物理/碰撞**：
   - Unity 的 PhysX 物理引擎使用浮点数，且内部状态不确定
   - 帧同步必须自行实现确定性物理引擎（定点数碰撞检测、定点数 Verlet 积分等）

## 🔍 详细解析

**定点数的实现原理**：
```
// 精度 0.001 (Q23.10 定点格式)
int fixedValue = (int)(3.14 * 1000);  // 3140
// 运算：加法、乘法后需右移 10 位还原精度
int result = (a * b) >> 10;
```

**帧同步的断线重连**：
- 服务器保存每一帧的所有操作序列
- 客户端断线后：
  1. 服务器发送当前完整状态快照（加速追赶）
  2. 客户端加载快照，从该帧开始回放后续所有操作
  3. 服务器可以加速发送操作（Chase Play / 追帧）帮助客户端赶上
- 结合状态同步思维：定期生成状态快照（如每 300 帧一个快照），减少重连时的追帧量

**状态帧同步**（折中方案）：
- 仍然按固定逻辑帧同步
- 但同步的不只是操作，还包括该帧变化了的状态数据
- 兼顾帧同步的定时性和状态同步的数据结构

## 💬 面试官常见追问
- "为什么不直接用 Unity 的物理引擎？" -> PhysX 基于浮点数，计算结果跨平台/跨帧可能不一致。帧同步要求完全确定性，必须自己实现定点数物理
- "帧同步怎么处理客户端卡顿？" -> 如果某个客户端卡住无法在时限内提交操作，服务器必须等他（LockStep 思想），否则全局不一致。超时后可以考虑踢掉该玩家或给 AI 补位
- "怎么验证不同客户端的一致性？" -> 定期对所有客户端做 checksum（如对整个游戏状态做 MD5），不一致说明有 bug

## ⚠️ 我曾经的误区 / 网上常见错答
- 误区：帧同步只要两边用相同的代码就能一致。浮点数的平台差异会导致相同代码产生不同结果，必须定点数
- 误区：断线重连只要重新加载状态就行了。帧同步下必须精确恢复到断线时的逻辑帧，否则重连后的操作会在错误的基准上执行，导致永久不同步
