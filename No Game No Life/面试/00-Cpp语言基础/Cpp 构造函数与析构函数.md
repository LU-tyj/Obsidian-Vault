## 一句话结论（自测用）
> Rule of Five（C++11）：如果自定义了析构函数/拷贝构造/拷贝赋值/移动构造/移动赋值中的任意一个，通常需要定义全部五个。核心原因：自定义析构意味着管理了特殊资源（堆内存/文件句柄），默认的浅拷贝和移动会导致 double free。

## 标准答案（结构化、可背诵，2分钟内讲完）
1. **默认生成的函数**：编译器默认生成：默认构造、拷贝构造、拷贝赋值、析构函数（C++11 加上移动构造、移动赋值）。一旦自定义任何一个，部分默认生成会被抑制。
2. **Rule of Three（C++98）**：如果自定义了析构函数、拷贝构造函数、拷贝赋值运算符中的任何一个，大概率需要管资源，必须定义全部三个。
3. **Rule of Five（C++11）**：在 Rule of Three 基础上加上移动构造函数和移动赋值运算符。管理堆资源的类应实现移动以支持高效转移。
4. **初始化列表 vs 构造函数体赋值**：
   - 初始化列表是真正的初始化（直接构造），构造函数体是赋值（先默认初始化再赋值）
   - const 成员、引用成员、无默认构造的成员**必须**用初始化列表
   - 初始化列表顺序由成员声明顺序决定，不是列表顺序
5. **虚析构函数**：作为基类的类必须声明虚析构函数。否则 `delete` 基类指针只调用基类析构，派生类资源泄漏。

## 详细解析

### 构造/析构调用顺序
```
构造：基类构造 → 成员构造（声明顺序）→ 构造函数体
析构：析构函数体 → 成员析构（声明逆序）→ 基类析构

多重继承：基类按声明顺序构造，逆序析构
虚继承：虚基类最先构造，最后析构
```

### = default 和 = delete
```cpp
class NonCopyable {
public:
    NonCopyable() = default;
    NonCopyable(const NonCopyable&) = delete;           // 禁止拷贝
    NonCopyable& operator=(const NonCopyable&) = delete; // 禁止赋值
};
```

### explicit 关键字
防止单参数构造函数的隐式转换：
```cpp
class MyString {
    explicit MyString(int n); // 禁止 MyString s = 5; 这种隐式转换
};
```

## 面试官常见追问
- 什么情况下编译器不会生成默认构造函数？（自定义了任何构造函数，编译器就不再生成默认构造）
- 移动构造在什么情况下不会被自动生成？（自定义了析构/拷贝构造/拷贝赋值/移动赋值任一，移动构造就不会自动生成）
- 为什么初始化列表比函数体赋值快？（少一次默认构造 + 赋值操作；对内置类型无差异）
- 析构函数可以抛出异常吗？（原则上不可以——析构抛出异常且栈展开时有另一个异常会导致 std::terminate）

## 我曾经的误区 / 网上常见错答
- **错**："默认生成的拷贝构造函数是浅拷贝" —— 对内置类型是值拷贝；对有拷贝构造的成员调用其拷贝构造；对指针确实是浅拷贝（只复制地址）
- **错**："初始化列表的顺序就是代码写的顺序" —— 执行顺序由类中成员声明顺序决定，与初始化列表书写顺序无关
- **错**："= default 就等同于不写" —— = default 显式要求编译器生成，即使在编译器本不会生成的场景也能强制生成
