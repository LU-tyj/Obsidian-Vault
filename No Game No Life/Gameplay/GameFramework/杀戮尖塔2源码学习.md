# 杀戮尖塔2代码解读杀戮尖塔2》

## 如何实现插队机制？

《杀戮尖塔2》实现插队系统有两个关键点：其一是基于 `Task` 和 `async/await` 的全异步回合制流程；其二是能够插入异步流程中的 [Hook](https://zhida.zhihu.com/search?content_id=271839968&content_type=Article&match_order=1&q=Hook&zhida_source=entity) 与 Model 架构。

### C#的异步流程基础

在深入解析之前，我们先简单回顾一下 C# 异步编程的两个基础概念：`Task` 和 `async/await`。如果你对此比较了解，可以直接跳过本节。

**1. Task 是什么？**

`System.Threading.Tasks.Task`（或 `Task<TResult>`）代表一个“可能还没完成的异步操作”。

- 代表一个正在进行的操作，可以在将来某个时刻完成。
- œ可以被 `await` 等待。
- 拥有状态：`Created`、`WaitingForActivation`、`Running`、`RanToCompletion`、`Canceled`、`Faulted` 等。

**2. async/await 是什么？**

`async` 修饰符用于表明该方法包含异步操作。`await` 操作符则用于异步方法内部，表示需要等待异步操作完成后再继续执行后续代码。

举例说明：

```text
public async Task 张三的一天()
{
    await 张三走路去学校();
    await 张三上英语课();
    await 张三回家();
}
```

以上伪代码描述了一个典型的异步流程：张三**先**走路去学校，到了学校**之后**再上英语课，上完英语课**之后**才回家。

### 《杀戮尖塔2》的异步流程架构

在《杀戮尖塔2》中，所有的战斗流程均是异步的。例如，玩家的回合阶段逻辑可以简化为如下伪代码：

```text
public async Task PlayerTurn()
{
    await 重置能量();
    await 抽牌();
    await 玩家操作阶段();
    await 弃置手牌();
    await 结束回合();
}
```

在这个基础之上，游戏是如何实现“插队”机制的呢？答案就在于 Model 与 Hook 的设计。

### 核心架构：Model 与 Hook

Model 与 Hook 是《杀戮尖塔2》战斗系统的基石，我们逐一拆解。

- **Hook**：Hook 是一个静态类，它提供了战斗中所有的钩子方法，负责将外部逻辑插入到既定的回合制流程之中。
- **Model**：战斗系统中的所有实体**全部**都是 Model。抽象基类 `AbstractModel` 定义了**所有**钩子方法的虚方法。其派生类包括卡牌基类 `CardModel`、遗物基类 `RelicModel`、能力/增益效果基类 `PowerModel` 等等。当某个 Model 需要在特定时机发动特殊效果时，只需重写对应的钩子方法即可。

打个比方：**Hook 是遍布游戏流程的“鱼钩”，而 Model 是池塘中的“鱼”**。当 Model 重写了某个钩子方法时，就意味着“鱼”咬上了“鱼钩”；当“鱼钩”起竿（Hook 被调用）时，“鱼”被钓起（执行效果）。

### 伪代码举例

首先是 Hook 类的定义，它负责在特定时机遍历并调用所有 Model 的钩子：

```text
public static class Hook
{
    // 玩家回合开始前的钩子
    public static async Task HookBeforePlayerTurn()
    {
        // 遍历战斗中所有实体，依次执行其钩子逻辑
        foreach (AbstractModel model in BattleManager.Instance.Models)
        {
            await model.BeforePlayerTurn();
        }
    }
    // ... 其他 Hook 方法
}
```

接着是 Model 的基类定义，定义了默认行为：

```text
public abstract class AbstractModel
{
    // 虚方法，默认不执行任何操作直接完成
    public virtual Task BeforePlayerTurn()
    {
        return Task.CompletedTask;
    }
    // ... 其他 Hook 方法
}
```

在加入 Hook 机制后，原本的玩家回合流程变为：

```text
public async Task PlayerTurn()
{
    await Hook.HookBeforePlayerTurn(); // 插入回合前逻辑
    await 重置能量();
    await 抽牌();
    await 玩家操作阶段();
    await 弃置手牌();
    await 结束回合();
}
```

此时，具体的 Model 只需实现 `BeforePlayerTurn`，即可在回合开始时中断原本的回合流程，插入并执行它的效果。

以“创造性 AI”（回合开始时获得能力卡牌）为例：

```text
public class CreativeAI : PowerModel
{
    // 重写钩子方法
    public override async Task BeforePlayerTurn()
    {
        await 获得随机能力卡();
    }
}
```

通过这种方式，我们便实现了回合流程中的第一个“插队”点。接下来，只需要在所有希望可以被打断的节点加上对应的 Hook 方法，就可以构建出一个复杂的战斗系统了（当然，这只是技术上的一小步）。顺带一提，《杀戮尖塔2》中定义了 100+ 个 Hook 方法，其系统深度可见一斑。

需要特别注意的是，本文主要专注于设计思路的讲解，省略了大量实现细节。如果你不熟悉Task异步流程的话，直接实现这套方案还是比较容易踩坑的，如果把思路打开的话，其实异步流程的实现并不局限于Task，使用协程、迭代器或者工作队列也可以实现类似的效果。笔者本人就是使用迭代器手搓的异步流程。



## ## GameAction实现

我们把玩家能做的操作都抽象成`GameAction`，这样做有两个好处：

- 把玩家的操作和实现分离，搭建从GUI到GameRun的桥梁
- 对于联机模块来说，方便玩家之间的同步。
  包括

```
DiscardPotion
UsePotion
EndPlayerTurn
UndoEndPlayerTurn
MoveToMapCoord
PickRelic
PlayCard
```

这些操作的执行通过`GUI`发送到游戏逻辑中。

### **如何执行GameAction**

杀戮尖塔采用的是类似**生产者-消费者**模型，维护一个内部队列。

```text
RunManager.Instance.ActionQueueSynchronizer.RequestEnqueue(GameAction);
public void RequestEnqueue(GameAction action)
{
//如果本操作需要战斗中，但是当前游戏没在，那么先进waiting队列。
    if (action.ActionType == GameActionType.CombatPlayPhaseOnly && CombatState == ActionSynchronizerCombatState.NotPlayPhase)
    {
    _requestedActionsWaitingForPlayerTurn.Add(action);
        return;
    }
    
//区分主机客机，如果是客机玩家，则把GameAction发包过去。如果是主机玩家或者单人游戏，直接入队。
    switch (_netService.Type)
    {
    case NetGameType.Client:
    {
        RequestEnqueueActionMessage message = new RequestEnqueueActionMessage
        {
            action = action.ToNetAction(),
            location = _messageBuffer.CurrentLocation
        };
        _netService.SendMessage(message);
        break;
    }
    case NetGameType.Singleplayer:
    case NetGameType.Host:
        EnqueueAction(action, _netService.NetId);
        break;
    }
}
private void EnqueueAction(GameAction action, ulong actionOwnerId)
{
    //如果是主机，广播一下操作给其他客机
    if (_netService.Type == NetGameType.Host)
    {
        ActionEnqueuedMessage message = new ActionEnqueuedMessage
        {
            playerId = actionOwnerId,
            location = _messageBuffer.CurrentLocation,
            action = action.ToNetAction()
        };
        _netService.SendMessage(message);
    }
    
    //进同步队列
    _actionQueueSet.EnqueueWithoutSynchronizing(action);
}
```

简单总结一下，假设A是主机，BCD是客机：

A发起`Action`，进同步队列，广播给BCD。

B发起`Action`，发送`RequestAction`消息给主机，主机收到后，进同步队列，广播给BCD。

private async Task ExecuteActions()
{
    _queueTaskCompletionSource = new TaskCompletionSource<bool>();
    _actionCancelToken = new CancellationTokenSource();
    //找到一个OK的Action
        GameAction readyAction = _actionQueueSet.GetReadyAction();
        //执行到没有可执行的Action为止
        while (readyAction != null)
        {
            await WaitForUnpause();
            if (readyAction.State == GameActionState.Canceled)
            {
                readyAction = _actionQueueSet.GetReadyAction();
                continue;
            }
            this.BeforeActionExecuted?.Invoke(readyAction);
            
            if (NonInteractiveMode.IsActive)
            {
                CurrentlyRunningAction = readyAction;
                await readyAction.Execute();
                AfterActionFinished(readyAction);
            }
            
            else
            {
                CurrentlyRunningAction = readyAction;
                readyAction.AfterFinished += AfterActionFinished;
                进入执行逻辑
                Task actionTask = readyAction.Execute();
                //轮询等待
                while (!actionTask.IsCompleted && !_actionCancelToken.IsCancellationRequested)
                {
                    await Engine.GetMainLoop().ToSignal(Engine.GetMainLoop(), SceneTree.SignalName.ProcessFrame);
                }
            }
            if (CombatManager.Instance.IsInProgress)
            {
                await CombatManager.Instance.CheckWinCondition();
            }
            readyAction.AfterFinished -= AfterActionFinished;
            readyAction = _actionQueueSet.GetReadyAction();
        }
        _queueTaskCompletionSource?.SetResult(result: true);
    }
}
