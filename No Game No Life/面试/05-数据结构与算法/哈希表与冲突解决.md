## 🎯 一句话结论（自测用）
> 哈希冲突四种解法：链地址法（拉链）、开放地址法（线性/二次/双重探测）、再哈希法、公共溢出区。STL unordered_map 用链地址法，扩容用渐进式哈希（rehash）。

## ✅ 标准答案（结构化、可背诵，2分钟内讲完）
1. **哈希表核心**：通过哈希函数将 key 映射到数组索引，平均 O(1) 查找
2. **冲突解决**：
   - **链地址法（拉链法）**：每个桶用链表/红黑树存储冲突元素（Java8+ HashMap 链表长度 >8 转红黑树）
   - **开放地址法**：冲突后找下一个空位（线性探测、二次探测、双重哈希）
   - **再哈希法**：使用多个哈希函数
   - **公共溢出区**：冲突数据放入独立溢出表
3. **扩容与渐进式哈希**：负载因子超过阈值（通常 0.75）时扩容。渐进式哈希在扩容期间同时维护新旧两表，查询时先查新表再查旧表，逐步迁移
4. **C++ unordered_map 底层**：链地址法，桶数组 + 链表

## 🔍 详细解析

### 链地址法 vs 开放地址法对比
| | 链地址法 | 开放地址法 |
|--|---------|-----------|
| 结构 | 数组 + 链表/红黑树 | 纯数组 |
| 缓存友好 | 较差（链表非连续） | 较好 |
| 负载因子 | 可 >1 | 必须 <1 |
| 删除 | 简单 | 需惰性删除标记 |
| 代表 | Java HashMap, C++ unordered_map | Python dict（早期） |

### 渐进式哈希（Redis 经典实现）
当负载因子超阈值时：
1. 分配新表（大小通常是旧表 2 倍）
2. 不一次性迁移所有数据，而是：
   - 每次增删改查时顺便迁移 1 个桶（或 N 个桶）
   - 查询时先查新表（用新哈希函数），再查旧表（用旧哈希函数）
3. 全部迁移完成后释放旧表

面试追问：扩容过程中插入/删除/查找怎么办？
- 插入：直接插入新表
- 删除：先在新表找，找不到在旧表找并删除
- 查找：先在新表查（新哈希函数），再在旧表查（旧哈希函数）

### Dictionary 原理（Csharp 面试常见）
Csharp `Dictionary<K,V>` 底层也是哈希表 + 链地址法。关键区别：
- 使用 `int[] buckets` 索引数组，指向 `Entry[]` 结构数组
- Entry 包含 key, value, hashCode, next（指向下一个冲突的 Entry 索引）
- 扩容时重新计算所有 key 的新哈希位置

## 💬 面试官常见追问
- "什么时候用 map 什么时候用 unordered_map？" -> 需要有序遍历时用 map（红黑树，O(logn)）；只需快速查找时用 unordered_map（哈希表，O(1) 平均）
- "哈希表扩容为什么通常是 2 的幂？" -> 位运算取模更快（`hash & (size-1)` 替代 `hash % size`）
- "负载因子为什么通常选 0.75？" -> 时间与空间的折中。太小浪费空间，太大冲突概率高

## ⚠️ 我曾经的误区 / 网上常见错答
- **误区**：以为 unordered_map 永远 O(1)。最坏 O(n)（全部冲突），需好的哈希函数
- **误区**：以为开放地址法简单高效。删除时需要惰性标记（tombstone），否则查找链断裂
- **误区**：不知道渐进式哈希是 Redis 的核心设计，面试追问扩容细节时会卡
