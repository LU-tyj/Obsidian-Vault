## 🎯 一句话结论（自测用）
> 三次握手：SYN -> SYN+ACK -> ACK，双方确认各自的收发能力正常。四次挥手：FIN -> ACK -> FIN -> ACK，因为 TCP 是全双工的，每个方向需要单独关闭。TIME_WAIT 状态在主动关闭方保持 2MSL，确保最后的 ACK 到达 + 让旧连接的报文在网络中消失。

## ✅ 标准答案（结构化、可背诵，2分钟内讲完）

**1. 三次握手（建立连接）**：

```
客户端                    服务器
  |                         |
  |------- SYN (seq=x) ---->|    1. 客户端：我要连接
  |                         |
  |<-- SYN+ACK(seq=y,ack=x+1) -| 2. 服务器：我收到了，我也要连接
  |                         |
  |--- ACK (seq=x+1,ack=y+1) ->| 3. 客户端：我收到了你的确认
  |                         |
双方进入 ESTABLISHED 状态
```

**为什么是三次而不是两次？**
- 两次握手下，如果第一个 SYN 延迟到达服务器，服务器回 SYN+ACK 后直接建立连接，但客户端已经超时放弃了——服务器白白维护一个无效连接
- 第三次 ACK 让服务器确认客户端的连接意愿是当前的、有效的

**2. 四次挥手（断开连接）**：

```
客户端（主动关闭）         服务器（被动关闭）
  |                         |
  |--- FIN (seq=u) -------->|    1. 客户端：我不发了
  |                         |
  |<-- ACK (seq=v,ack=u+1) -|    2. 服务器：知道了（但我可能还有数据要发）
  |                         |
  |<-- FIN (seq=w,ack=u+1) -|    3. 服务器：我也不发了
  |                         |
  |- ACK (seq=u+1,ack=w+1) ->|   4. 客户端：好，再见
  |                         |
客户端进入 TIME_WAIT，服务器进入 CLOSED
```

**为什么是四次而不是三次？**
- TCP 是全双工的，每个方向独立关闭
- 服务器收到 FIN 后可能还有数据要发，先 ACK 确认收到，等数据发完再发 FIN
- 中间的 ACK 和 FIN 不能合并（可能有时序重叠，但通常是分开的）

## 🔍 详细解析

**TIME_WAIT 状态**（网易互娱高频追问）：

- 主动关闭方在发送最后一个 ACK 后进入 TIME_WAIT，持续 **2MSL**（Maximum Segment Lifetime，通常 2 分钟）
- **为什么需要 TIME_WAIT？**
  1. 确保最后的 ACK 能到达服务器——如果 ACK 丢失，服务器会重发 FIN，客户端还在 TIME_WAIT 就能回复
  2. 让旧连接的所有报文在网络中"自然消亡"——防止旧连接的报文误入新连接（相同四元组的情况下）
- **TIME_WAIT 过多的问题**：大量短连接场景下端口被占满（端口号 16位 = 65535个，减去预留约 3 万可用）
- **解决方案**：SO_REUSEADDR、调整 tcp_tw_reuse、使用长连接

**TCP 状态转换图（关键状态）**：
```
CLOSED -> LISTEN -> SYN_RCVD -> ESTABLISHED -> FIN_WAIT_1 -> FIN_WAIT_2 -> TIME_WAIT -> CLOSED
```

## 💬 面试官常见追问
- "如果三次握手的最后一次 ACK 丢失了怎么办？" -> 服务器没有收到 ACK，会重传 SYN+ACK。客户端进入 ESTABLISHED 开始发数据，数据包中带有 ACK 序列号，服务器收到数据也相当于收到了 ACK
- "能不能用两次握手？" -> 不行，原因见上。两次握手会导致历史连接问题
- "SCTP 的四次握手知道吗？" -> SCTP 使用四次握手 + Cookie 防止 SYN Flood 攻击

## ⚠️ 我曾经的误区 / 网上常见错答
- 误区：TIME_WAIT 是为了等服务器。实际上客户端进入 TIME_WAIT 等 2MSL，服务器收到最后一个 ACK 后直接 CLOSED
- 误区：四次挥手中间两步可以合并。严格来说，如果服务器收到 FIN 时没有数据要发了，可以将 ACK 和 FIN 合并为一个包——变成三次挥手。但通常中间有数据没发完，所以是四次
